## 泰式星盘画法

默认圆盘现使用 `ThaiOrbitWheel.tsx` 的多层圆环、星位标记与关系连线，页面仍为原米白主题。点的位置读取当前用户 `points.*.longitudeDegrees`，以实际泰式上升放在左侧；星座与宫位读取 `points` 和 `houses`。密集星体只调整标记所在的径向层，保留原始角度。传统 GitHub 画法可以切换，九分盘与三分盘仍使用下述传统分区。

连线逐对读取上游 `relationships` 的对宫、四方、三方与六合分组，不自行增加西洋相位容许度算法，也不使用 `numberCandidates` 生成预测。点击星位或连线可查看对应星体、星座内度数、星体经度、宫位，以及本次计算所用生辰、时区、地点与坐标；键盘和触屏可从折叠列表选择相同项目。关系按星座分组，不表示两颗星体形成精确角度。八字四柱继续单独计算，不将天干地支与星体编号硬作一一对应。

`ThaiRasiWheel.tsx` 的几何、星座方位及星号放置点改编自上游固定提交的 [`scripts/render-readme-chart.cjs`](https://github.com/kongesque/thai-astrology/blob/445577e7cbc8c09ddc98f2ec016cd3d1e32940fb/scripts/render-readme-chart.cjs)。使用圆形外环、内部直线分区、正上方白羊、逆时针排列；泰文数字表示星体、红色 `ลั` 表示上升、`*` 表示ตนุเศษ。中央数值在本命盘显示本命太阳在星座内的度、分；切换分盘时显示分盘名称。

界面读取当前账号实际计算出的 `charts.rasi/navamsa/drekkana.channels.thai`，没有把仓库的 1782 年固定示例冒充用户个人盘。修改生辰后按资料版本重新加载；退出或切换账号时隐藏前一账号的结果，未完成的请求会取消。未知时间不展示完整盘。

## 本次使用的规则

| 部分     | 固定口径                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------- |
| 主算法   | `calculateThaiHoroscope`，สุริยยาตร์ Suriyayatra；不使用旧包装 API 的默认 legacy 算法                               |
| 日期     | 表单接受公历或现代佛历显示；服务端保存公历                                                                          |
| 输入时间 | 出生地当地民用时间；Python ZoneInfo 计算历史 UTC 偏移，拒绝 DST 不存在或重复时刻                                    |
| 上升参照 | 出生日期、坐标的日出，四舍五入至分钟；固定 Anto 升起时长                                                            |
| 行星时间 | 出生地历史 UTC 偏移换算至曼谷历史 `+06:42:04` 框架，24124 秒；不是全流派统一的强制历元                              |
| 十二宫   | whole-sign，泰式上升所在星座为第一宫；宫主和落宫读取工具输出                                                        |
| ทักษา    | `weekday-0600`，06:00 换日，不另采用周三夜间替换罗睺规则                                                            |
| 泰历     | 使用 `calendar.thaiLunarDate`；不是日月夹角推得的 `calendar.lunarDay`，也不是 lunar-python 的中国阴历/佛历          |
| 行运     | 每次请求使用当前曼谷日期及分钟；展示星位与落入的本命宫，是此刻快照                                                  |
| 主题映射 | 关系第7宫/ศรี，金钱第2宫/มูละ，家庭第4宫/บริวาร，工作第10宫/อุตสาหะ；为 WANJAI 版本化象征映射，行动正文仍是编辑内容 |

泰国占星存在不同流派。这个版本没有声称代表所有泰国规则。海外地点仍沿用固定 Anto 时长，不能把其上升误称为全球几何天文学上升；需要与同流派、同时间口径的参考盘核对。星座关系也不能被说成精确度数相位和容许度。

### 缺资料时的行为

- 完整本命盘时间未知：保留公历星期与可确定的泰历日期，不填中午，不显示完整个人星位、上升、宫位、ทักษา或本命宫行运。首页生日简版另外保留太阳参考的可能范围，并显示三周期的公共行运位置；相对太阳的位置不当作本命宫位，详见下方免费入口。
- 时间已知但坐标未解析：可显示星期、泰历、ทักษา，不默认放到曼谷，不生成完整盘。
- 地点可由明确 GeoNames ID、唯一英文/泰文目录名，或用户提供的一对经纬度确定。目录搜索泰国有 83 点，包括 77 个府治点和 6 个额外城市点；府治坐标不等于具体医院。
- 当前选择器支持泰国、中国、越南、美国目录搜索，每次最多返回 100 条；较大列表应输入城市名检索。其他地区可填写出生地和坐标，再核对时区。
- 部分旧城市名未必在目录中，例如 Pattaya；遇到这种情况提示补地点，不能偷偷匹配其他城市。
- 泰历支持 CE 1582–2076；资料表单日期范围仍为 1901 年至出生地今天。无日出等算法错误会显式报错，不降级编造上升。

## 实现位置与接口

- `scripts/thai-engine.mjs`：本地 Node 引擎适配。FastAPI 用无 shell 的 JSON stdin/stdout 调用，固定 UTF-8，12 秒超时，最大两路计算，不把出生资料传给排盘外部服务。
- `backend/app/thai.py`：历史时差、指纹、紧凑模型上下文。SQLite 按用户和输入/引擎指纹保存本命结果，资料 revision 独立附在响应上。
- `GET /api/thai-locations`：离线搜索目录，无账号资料。`country=&level=auto` 接收组合出生地点，例如“河北省，邯郸市”，识别国家、省府和城市；唯一精确结果自动确认，重名地点返回候选列表。完整 CN/TH GeoNames 聚居地索引由 `pnpm setup:locations` 构建到 `data/birth-locations.sqlite3`，不要求在线地理编码密钥。`level=province` 提供 34 个中国省级地区与 77 个泰国府级代表点，数据及翻译在 `backend/content/birth-regions.json`；许可见 `public/licenses/NOTICE.txt`。
- `GET /api/thai-chart`：登录后读取本人资料、计算/读取缓存，返回完整或部分状态。
- `GET /api/thai-transits`：登录后计算此刻行运，不缓存成永久“今日运势”。
- `src/lib/thai.ts`：按账号和 revision 加载，取消旧请求，拒绝过期资料版本。
- `ThaiChartPanel.tsx`：排盘、分盘、宫主、ทักษา、泰历、行运和规则说明；四语言界面，泰式固有名词保留泰文。
- `ThaiBasis.tsx`：今日陪伴、问题和报告的实际泰式依据。首页改由 `useFortune` / `thai-fortune.mjs` 显示当前生日及对应日、周、月的实际位置与规则依据。原西式生日区间文案不作为主线。
- `providers.py` / `main.py`：默认泰式工具；明确八字关键词才调用八字上下文，明确行运关键词再加行运工具。词路由是可检查的简单实现，不声称具备完整自然语言意图识别。

聊天锁在等待工具前预留，防止工具运行时同账号修改档案或同时发起第二轮对话。传给真实模型时默认移除中国八字 chart，避免模型混用。用户档案、情况、历史和记忆都是数据，不能覆盖系统规则。工具不可用时如实标记 unavailable。

### 免费生日与三周期入口

`POST /api/fortune` 接收必填出生日期与 today/week/month，时间和城市可空，不要求账号；不创建用户或保存档案。`POST /api/thai-chart/preview` 与 `/api/thai-transits/preview` 为访客提供同一计算口径，完整度不足时返回部分状态。三接口共用原有大小限制、限流、两路计算信号量及 12 秒子进程超时，不调用外部排盘服务。

首页计算位置后使用本站 `wanjai-thai-guidance-1` 规则选取四语言行动建议，**规则不是上游库提供或验证的事件预测模型**。未知出生地点按 UTC+14 至 UTC−12 保留可能时刻，未知时间保留整日；太阳换座保留双参考，只有明确时分和可解析地点才用上升宫位。精度、公式、同星座可能得到相同简版建议的原因与验证方式详见 [FORTUNE_RULES.md](FORTUNE_RULES.md)。不提供年度运势。

## 如何继续验证

1. 建立获得同意、去标识的同流派参考集。每例固定出生日期/时分、坐标、历史时区、日出取整、换日和宫制。由泰国本地老师/历书提供参考星位、上升、宫主、ทักษา及泰历；不要用本库自行生成“标准答案”。
2. 在开发前锁定容差和分层：普通时刻、06:00附近、日出附近、星座边界、1920曼谷改时、国外DST、闰月闰日。分别报告角分误差、星座/宫位匹配率、异常比例；列出失败例。
3. 解读由泰语母语评审和同流派从业者盲评。指标包括工具事实引用正确率、无依据断言率、术语自然度、是否贴合用户问题。评审当前尚未开展，不伪造评分。
4. 要评价事件预测，先定义可观察结果、时间窗口和基准组，做前瞻性留出验证，并报告样本量、置信区间、失访与负例。禁止事后修改结论以适配用户反馈。
5. Roxy/模型记忆另外测跨账号泄漏、误记和删除；手相另建图像标注集，解梦另核对授权内容及引用。这些不能用排盘测试结果代替。
