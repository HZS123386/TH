# APP 西洋占星报告审查与模型切换

当前仅在本地 Flutter APP 的西洋占星报告接口启用。H5、落地页继续使用原有报告流程；没有上传或部署服务器。

## 实际调用顺序

1. 现有 Roxy 适配器调用 `/astrology/natal-chart`，核对出生输入回显、热带黄道、Placidus、真实交点、行星位置和相位容许度。
2. 程序区分展示与解读材料。APP 在时间未知时按当地 12:00 展示完整估算盘（含月亮、上升、宫位和相位），逐项标记 `estimated`；送入报告整理及审查的材料仍剔除月亮、宫位、角度、相位、接近换座边界的位置及含宫位的原始解释。
3. 先检查可用事实和 Roxy 原始解读。未知出生时分的资料，若只含严格限定字段的可靠行星数值、无任何解释原文或额外字段，直接使用程序完成来源核验，记录 `source_review` 和版本 `western-numeric-source-1`；其余资料仍由审查模型逐项检查。字段扩展、来源原文或精度不符时不走数值快速检查。没有返回原文的项目保留为数值事实，不伪造 Roxy 原文。
4. 整理模型根据通过检查的材料生成六维报告：个人特质、事业发展、财务习惯、感情与家庭、需要留意的地方、行动建议。
5. 程序检查 JSON 结构、语言、主题引用、重复段落和财务推断；审查模型进一步核对摘要和六维中的解读、例子、两条建议，共 25 个公开字段，检查含义是否得到引用支持及跨章节矛盾。
6. 最终审查不通过时，审查模型必须指出字段和逐字匹配的原句或语义完整的短句。程序为这些原句分配固定编号；整理模型只按编号返回替换文本，没有修改原句位置或扩大范围的权限。程序保留其他正文、事实引用和顺序。最多进行两轮定向修正，每轮之后都重新审查整份报告；仍不通过就失败，不下发草稿或用示例代替。
7. 全部通过后一次性保存并返回报告。刷新或返回页面可以读取已完成报告，生成过程中不向前端流式展示未经审查的文字。

当前整理模型为 `qwen3.7-plus`，审查模型为 `kimi-k3.1-pro`。两者都是服务端调用，客户端没有供应商密钥。审查只检查来源忠实度、表达边界、语言和建议质量，不代表验证现实事件预测准确率。

## 配置

统一根目录下的 `TH/.env` 保存本地配置。角色配置不会改写 H5 使用的通用 `BAZI_REPORT_PROVIDER` 或供应商配置。

```dotenv
WESTERN_REPORT_PROVIDER=qwen
WESTERN_REPORT_MODEL=
WESTERN_REVIEW_ENABLED=true
WESTERN_REVIEW_PROVIDER=kimi
WESTERN_REVIEW_MODEL=kimi-k3.1-pro
WESTERN_REVIEW_FALLBACK_PROVIDER=
WESTERN_REVIEW_FALLBACK_MODEL=
```

`*_PROVIDER` 选择现有供应商连接：`kimi`、`qwen`、`deepseek`、`openai`。仍需相应的 `*_API_KEY`、`*_BASE_URL`、`*_MODEL`。角色的 `*_MODEL` 非空时覆盖该角色的模型名；为空时沿用该供应商的通用模型名。修改后重启本地 API。

例如，已开通另一供应商后替换 Kimi：

```dotenv
WESTERN_REVIEW_PROVIDER=deepseek
WESTERN_REVIEW_MODEL=<该账号实际可用的模型 ID>
```

也可以使用同一个 Qwen 连接、两个不同模型，而不改变 H5 模型：

```dotenv
WESTERN_REPORT_PROVIDER=qwen
WESTERN_REPORT_MODEL=qwen3.7-plus
WESTERN_REVIEW_PROVIDER=qwen
WESTERN_REVIEW_MODEL=<该账号实际可用的另一模型 ID>
```

以上替换配置是用法示例，不表示这些替代模型已经通过真实联调。需要选择支持现有 Chat Completions 和 JSON 输出的模型，并核对其区域、参数、限流与模型 ID。程序禁止完全相同的服务地址及模型同时担任整理和审查；同系列模型仍可能有相似盲点。

备用供应商只用于主审查服务不可用的情况，而且必须明确配置。主模型对内容作出拒绝后不会换一个模型尝试放行。本地不会自动充值或选择未配置的供应商；各次 API 调用仍按供应商的额度和账单规则计算。赠送额度耗尽且没有可用备用连接时，报告失败，页面可重试。

## 1110 PPT 的报告文字约束

来源为桌面 `1110.pptx` 第 4–11 页，包括第 11 页图片形式的话术对照表，按项目内部内容规则执行，不把演示文稿中的概括表述当成法律审核结论。

| 报告审查点 | 当前处理 |
| --- | --- |
| 保证准确、准确率统计、最准/第一、必定转运、改运化解、具体事件预测 | 程序检查明显表述，模型按含义检查；替换为有依据的习惯倾向或行动建议 |
| 灾祸、劫难、诅咒及焦虑引导付费 | 不生成恐惧式结论和紧急解锁话术 |
| 大师、真人亲测、王室或宗教背书、寺庙和开光 | 不冒充身份或认可，不把这些内容写成报告依据或服务效果 |
| 彩票、中奖、投注、幸运号码、数字招财避灾 | 不提供此类结论，不将西洋本命盘转换为号码预测 |
| 免费、订阅、价格、效果退款、免责和限时营销 | 报告不自行编造商业条款、单方调价权或一概免责；价格页、购买页仍需独立核对实际商品配置 |
| 分享转运与个性化危险提示 | 不以传播或付费承诺运势改变，不伪造“你的命盘有变”等恐惧提醒 |
| 体系和语言 | 保留西洋占星规则和用户所选报告语言，不引入泰历、七曜或七位数字体系冒充当前测算 |

出生日期、星盘度数、普通时间安排中的数字保留真实值；PPT 关于王室、彩票语境的提醒用于内容语义检查。广告素材的泰语译文、图片元素、订阅披露和收费转化流程需要在对应页面另行验收，句子改写不能代替这些检查。

被标记的句子若有依据但表述太绝对，就改成贴合事实的条件表达；若原本没有依据，就改为有依据的内容或建议。禁止仅用近义词隐藏同一项承诺或错误结论。审查模型的自由文字诊断作为不可信数据传入，真正的纠错要求由应用按固定问题类型生成。

## 更换模型的影响

| 项目 | 影响 |
| --- | --- |
| Roxy 星盘 | 不受影响；仍由原有排盘接口计算和缓存 |
| 审查结论 | 新模型对无依据推断、语言自然度、重复内容的识别能力和宽严程度可能变化，需要重新验证 |
| 文字风格 | 换审查模型会通过纠错间接影响文字；更换整理模型会直接影响表达和详细程度 |
| 耗时 | 与模型速度、推理、上下文和重试有关；本流程有前后两次审查，比单次整理多出请求 |
| 成本 | 增加审查及可能的定向改写成本；按实际 token 与供应商账单核对，未收到 usage 时不能按零费用理解 |
| 缓存与历史 | 模型、服务地址、流程版本进入报告生成版本及内容缓存；新生成不沿用旧配置结果。已通过审查的历史报告仍可读取 |
| 数据处理 | 更换供应商或区域意味着需要重新确认数据处理范围；只发送必要星盘事实和解读，不发送姓名、城市文字或聊天历史 |

## 失败边界及追溯

- 后台在现有 `western_reports.payload._audit` 保存来源/成稿摘要哈希、规则版本、实际审查模型、通过/拒绝、检查目标、问题类型和耗时。拒绝时只保留内部诊断，不保存可展示草稿。
- 模型 token 使用沿用 `report_model_usage`，通过 `report_id`、`phase=western_app` 与各阶段关联；失败的模型调用也记录使用情况，审查覆盖校验与最终内容审查通过分别判断。单句修改另记目标字段与修改前后哈希；其他正文保持逐字一致。
- 当前进程内的实际审查模型调用串行执行，缓存命中在模型工作队列之外返回，其他用户的慢请求不会挡住已有缓存。模型总并发限制继续生效。遇到短期 429 限流时按不超过 15 秒的 `Retry-After` 等待，在阶段最多两次尝试的范围内重试；超出等待范围或仍失败则关闭输出。不会通过改写报告绕过额度或服务错误。
- 同一来源的审查在账号或游客作用域内缓存，可被不同语言报告复用；成稿按内容及语言分别审查。所有缓存仍隔离身份。
- 最终审查只携带整份报告实际引用的事实，以及所引用相位两端的行星事实；完整 25 字段、所有章节和跨章节矛盾检查继续保留。来源审查仍检查全部原始事实。请求 JSON 去除多余格式空白，系统提示保持稳定，便于供应商复用上下文缓存。新任务的整理及各次审查分别记录 `elapsed_seconds`。
- 2026-11-12 后续优化：报告整理版本升为 `fate-western-reading-9`，要求模型输出紧凑 JSON，保留原有正文长度与详细程度。每次真实模型调用单独持有工作名额，供应商退避等待期间释放名额，实际模型并发上限与最多尝试次数不变。内部审计增加 `attempts`、固定类别 `attempt_failures` 及排队、模型调用、重试等待耗时；不保存供应商原始错误或公开草稿。
- 同一内容的拒绝结论可以缓存；最终审查拒绝后，用户主动重新生成会取得新的草稿尝试标识，并携带上一轮问题作为不可信诊断，避免一直卡在同一份失败草稿。新草稿依然需要通过完整审查，不能借重试跳过拒绝。
- APP 的报告额度在创建任务时按一次报告尝试计数，内部来源审查、句子修改及最终审查不重复占用报告次数；供应商 token 使用仍逐次记录并按其账单计费。缓存读取、重复点击已在运行的任务不重复计数。
- APP 生成状态增加 `generation_progress`：资料检查占前 20%，完整接收摘要、六个主题的解读、例子及各两条建议后推进至 72%，整份审查与必要的句子修正占其余阶段；仅报告通过全部校验并保存为 ready 后返回 100%。过程计数保存在现有报告记录中，重试中的进度不回退，未完成字符串不计数。接口只下发阶段、百分比、已整理主题，不下发未经审查的正文或内部问题；失败保留最后进度并限制在 99% 以下。此接口不修改 H5 的任务与进度协议。
- 整体任务最长 480 秒，任务有效期 510 秒，避免新增审查导致原 180 秒任务过早失效。模型各阶段仍保留独立超时和有限尝试。
- APP 报告整理和审查的读取超时均为 60 秒，阶段总上限分别仍为 140 秒和 100 秒；超时后可在原有最多两次尝试内重试，不追加无限请求。H5 共用传输的默认读取超时仍为 25 秒。中文建议要求分三到四个短句说明第一步、具体做法和检查方式，目标为每条 70–110 个汉字；原有最低长度、语言、依据与最终审查校验继续执行。失败的整理和审查记录在内部审计中保留固定 `failure_code`，不向用户泄露原始模型错误或未审查草稿。
- 429 响应只提取固定类别，区分服务过载、调用限流和额度问题，不保存或下发供应商原始错误信息。APP 报告读取接口通过 `failure_reason=service_busy/service_timeout` 提供可本地化的提示，保留星盘和重试入口；历史任务的普通 429 也能显示服务繁忙。2026-11-12 的实测曾确认 Kimi 小请求和完整审查均返回 `engine_overloaded_error`，服务恢复前不能把本地回归通过写成报告已生成成功。供应商错误含义参考 [Kimi 故障排查](https://www.kimi.com/help/kimi-api/api-troubleshooting)。
- 旧的未审查报告保留在数据库，但启用本流程后不再作为通过审查的报告下发，需要重新生成；已有审查记录和内容哈希匹配的历史报告可继续查看。
- 本地开发完整阅读与生产内购权限边界保持原实现。审查通过不创建 StoreKit 权益，也不表示 iOS 真机内购已验收。

## 验证与后续接入

2026-11-12 第二轮耗时优化记录在 `TH/output/western-latency-20261112/`。同一份未知出生时分的中文资料、相同 Qwen/Kimi 型号，独立测试数据库无生成缓存时：优化前 40.391 秒；优化后第一次 56.265 秒（正文两次尝试），第二次 39.796 秒（正文一次尝试）。三份均通过整份审查。数值来源核验不再产生模型请求；来源含原文或完整出生时间时仍使用原模型流程。重复读取测试中的任务缓存耗时为 0.035–0.078 秒，不代表浏览器端到端加载时间。

这些少量样本不能证明稳定的总耗时下降，尤其不能把此前供应商繁忙时的 83–89 秒与现在直接比较为提速比例。可确定的是减少了一次纯数值来源的模型调用，以及通过并发测试验证退避等待不会阻塞其他任务。当前账号模型列表未开放 Highspeed，因此未更换审查模型。相关后端 123 项测试、共用传输的泰式解读回归 55 项以及 Ruff 检查通过，共 178 项；包含数值快速检查的严格字段限制、来源含文字时保留模型检查、拒绝时不发布、完整 25 字段审查及实际并发限制。

2026-11-12 APP 进度条验证：Flutter 37 项测试、相关后端 119 项回归通过，包含四种已知/未知时分与完整/试读组合的自动跳转、中途离开再继续、失败不跳转、进度上限，以及流式计数不泄露草稿。模型服务速度仍取决于实际供应商响应，进度百分比不表示预计剩余时间。

真实英文报告 `FATE-CDDF7A5991` 约 83.4 秒完成并通过整份审查，页面观察到 5%、42%、51% 的实际内容进度及对应的主题完成数，刷新后恢复同一任务；任务完成后重新载入进度页，自动进入对应解读。实测发现每秒轮询会触发共用接口每分钟 30 次的限流，现改为每 3 秒查询，相关五项页面测试已复测通过，并覆盖短暂查询失败后的自动恢复。截图及计数记录位于 `TH/output/reading-progress-20261112/`。此耗时为单次观察，不能作为生成时间承诺。

2026-11-12 本地速度优化：在一份已完成中文报告上，最终审查所需事实从 36 项减少到 11 项，序列化材料从 20,499 字节减少到 15,062 字节，减少约 26.5%；25 个公开字段、整份原文及相位端点依赖保持完整。缓存不再等待实际模型审查的串行队列，未命中缓存的模型工作仍限制为一项。新增测试验证未知引用不会被静默删除、来源审查保持完整、缓存不会被慢请求阻塞，以及实际并发限制保持有效。相关后端回归 116 项通过。

真实基准记录位于 `TH/output/western-speed-20261112/`。对比中供应商再次返回 `model_overloaded`，没有得到同等服务条件下的成功耗时对比，因此不宣称已经缩短到固定秒数。此前用户这次任务总耗时 56.969 秒，包含来源和草稿缓存命中，以及最终审查失败后重试；它不是新报告的冷启动耗时。原已通过审查的报告保留，刷新直接读取。

自动化测试位于 `backend/tests/test_western_review.py`，覆盖前后审查顺序、完整 25 字段检查、拒绝不下发、两轮以内的句子修正、明确备用、故障关闭、游客隔离、模型版本和内容哈希。相关回归还包含原西洋排盘、原报告、共用模型传输和 H5 报告测试。

本轮相关后端回归 116 项通过，Flutter 客户端 27 项回归通过。真实模型检查使用虚构出生资料：中文、泰文、越南文六维报告及未知出生时分的英文报告通过来源及最终审查；另把一条实际被拒绝的泰文句子按固定编号重放，其他 24 个公开字段和全部事实引用保持一致，替换后整份报告重新审查通过。测试是样本级接口与内容流程验证，不代表现实预测准确率或泰语母语阅读验收。

| 实测样本 | 观察耗时 | 结果 |
| --- | --- | --- |
| 中文、已知出生时分 | 约 91 秒 | 两次程序校验尝试后通过最终审查 |
| 泰文、已知出生时分 | 约 76 秒 | 两次程序校验尝试后通过最终审查 |

这是本机、单组虚构出生资料的链路观察，包含模型调用与部分自动纠错，不能视为移动网络时延承诺。较早的尝试曾因无依据推断、混合语言、修改范围或重复表达失败，均关闭输出；这些失败用于完善校验和修复机制，没有计作通过样本。
