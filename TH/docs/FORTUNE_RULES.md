# 免费三周期运势的计算与解读

日期：2026-11-06。入口为语言确认 → 生辰填写 → 今日、本周、本月。出生日期必填，具体时分和城市选填；年度入口与服务端年度参数已移除。四语言使用同一计算结果。已新增 OpAstro 周期重点筛选与 Qwen 四语言生成，接入范围、报告固定取样、费用、缓存和校验详见 [OPASTRO_INTEGRATION.md](OPASTRO_INTEGRATION.md)。下文的 v1 分类与参考段落保留为即时展示及生成失败时的回退。

## 数据与计算范围

- 访客档案存储于浏览器 `wanjai.birth`；调用本机 `POST /api/fortune` 计算时发送资料，不在用户、档案或聊天表中建立记录。清理浏览器会清掉这份访客资料。
- 账号没有档案时预填访客资料，由用户确认保存才绑定；已有账号读取其服务端档案，退出后恢复原访客资料，不复制账号资料到访客空间。
- `thai-astrology@0.3.2` 的สุริยยาตร์行星位置为计算输入，沿用 `wanjai-suriyayatra-1` 适配口径。不调用西式生日区间函数，不用日期哈希、随机数或固定幸运分数。
- 完整时分与可解析的地点：读取同一本命引擎的上升星座，以整宫制计算行运落宫。
- 只有生日或缺少精确地点：以泰式出生太阳所在星座作为参考，计算行运相对星座位置。**相对位置不是本命宫位**，不生成虚构上升或宫位。
- 已知城市而时间未知：保留出生地当日第一个和最后一个有效民用分钟；DST 午夜缺口跳至有效分钟，折返保留两端，整天被跳过的日期拒绝。明确提供但不存在或重复的时分继续拒绝。
- 城市未知：出生日期时段保留 UTC+14 至 UTC−12 的完整可能区间；日期单独输入最多约 50 小时，已知时分时约 26 小时。不会把缺失城市默认为出生在曼谷。
- 此范围中太阳最多跨一个星座边界，端点为同一星座时采用该参考，否则保留两个。不同参考给出不同类别时显示混合结果；补充时间城市可缩小范围。
- 未知时间不计算ทักษา或其占星星期；泰历仅展示整日一致的值。日期简版的分辨率较粗，同一泰式太阳星座的不同生日可能得到相同建议。

## 周期与规则

所有运势日期以曼谷时区为准；今日使用请求时当前分钟，周为周一至周日的 7 个每日 12:00 时点，月为当月每日 12:00 时点。周/月覆盖整个对应周期，包含尚未到来的日期；未来时点仅计算天体位置。

每个时点计算 `position = (transit.sign - reference.sign + 12) % 12 + 1`。完整盘的 reference 为上升星座，其余为可能的泰式太阳参考星座。以下为**本站自编、有版本的行动建议规则**，不是已核验的泰国老师传承或上游预测规则：

| 主题 | 计算星体 | 推进类位置   | 整理类位置 |
| ---- | -------- | ------------ | ---------- |
| 感情 | 金星 ๖   | 5、7、11     | 6、8、12   |
| 金钱 | 木星 ๕   | 2、5、9、11  | 6、8、12   |
| 家庭 | 月亮 ๒   | 1、4、5、9   | 6、8、12   |
| 工作 | 水星 ๔   | 3、6、10、11 | 8、12      |

其余位置为平稳类。每个出生参考独立统计所选周期的三类数量，单类比例达到 60% 时选取该类，否则为混合；多个不确定出生参考必须类别一致，否则仍为混合。规则版本 `wanjai-thai-guidance-1`。行星移动慢时，今日、周、月可能选择相同类别，不为了文案差异伪造不同结论。首页焦点使用用户所选关心主题；其他主题仍各自计算。

API 返回出生参考、采样日期和时分、每个星体的星座与经度、相对位置、分类、类别计数、引擎与规则版本。页面“查看计算依据与我的资料”可以展开查看实际证据，计算失败显示错误和重试，不回退成固定示例。生辰、账号、周期、语言或曼谷日期变化时重取结果；旧请求取消，过期资料结果不显示。

首页点击今日／本周／本月后，在按钮下直接展示寄语、连续段落解读，以及感情、财务、家庭、工作四项结果。显示本次使用的生日和参考类型，资料不全时提示相对位置简版，太阳跨界时保留双参考说明。

计算分类仍采用上述 v1 规则。段落生成器为 `wanjai-calendar-narrative-1`，文案位于 `backend/content/fortune.json`。引擎同时返回当前曼谷日期、公历星期、泰历盈亏日、月亮实际经度及相对出生参考星座的位置。日运用当前月亮位置、七日星期主题和泰历月相阶段组合正文；周运读取周初／周中／周末的真实取样，月运读取月初／月中／月底取样。出生参考有歧义时保留范围提示，不选取一个星座冒充确定值。泰历缺失时不猜测月相。四主题段落由各自计算类别选择，不再使用记开销等固定任务清单。

这些是本站公开的编辑解读规则，天体计算与文字含义分别记录版本；不声称上游提供了这些解读，也不把星期或月相主题当作已验证的事件预测。没有随机数、日期哈希、幸运分数或为文案强行改变分类。正文按真实日历因素更新，同类星象仍可能保持相近倾向。配置可用模型后，新周期可按额度调用 Qwen 生成解读，刷新优先复用缓存；未配置、额度不足或生成失败继续使用上述参考段落。“聊聊这份运势”收到同一周期的计算依据与当前账号已生成的解读。

页面在曼谷午夜重取结果，并以一分钟检查和窗口聚焦／页面恢复事件处理后台休眠。改生辰、切换账号、语言、周期或日期时清除不匹配的旧结果；重试和迟到响应处理保留。

## 如何验证

`backend/tests/test_fortune.py` 检查三周期日期范围、闰月和跨年周、曼谷换日、生日变化、未知时间与地点、太阳边界双参考、完整盘与原引擎上升一致、DST 缺口与折返、必填和年度参数拒绝、访客计算不写库且不覆盖账号、引擎故障不伪造结果。`e2e/fortune.spec.ts` 在桌面和手机操作语言、生日门槛、滚轮、真实 API 三周期、四项结果直接可见、周期建议与服务端分类对应、修改与持久化、语言切换和账号确认绑定，并检查计算失败后清除旧结果、重试恢复、快速切换时迟到响应不能覆盖当前周期。聊天测试另核对模型收到所选周期的同一份建议。

`backend/tests/test_fortune_narrative.py` 检查连续三天正文实际变化、不同生辰、四语言、三周期取样、交界双参考、午夜与缺失泰历；`src/lib/fortune.test.tsx` 使用模拟时钟检查页面停留跨午夜和休眠后恢复时的重新计算。

运行 `pnpm test:api`、`pnpm test:e2e e2e/fortune.spec.ts`、`pnpm verify:thai`。引擎原有 150 项检查及独立日出对照见 [GITHUB_INTEGRATION.md](GITHUB_INTEGRATION.md)。这些测试验证实现与来源，不等于预测准确率。当前没有泰国本地老师对解读规则的盲评，没有未来事件的前瞻性验证，因此不声称“准确率 99%”或已通过专业预测认证。今日陪伴、七步路径和长篇报告的固定编辑正文不因首页接入而自动成为计算预测。
