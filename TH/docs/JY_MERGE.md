# JY 页面与本地 React 能力合并

来源：`jm1314-bit/wanjia` 的 `JY` 分支，提交 `b8a0fd93a9ba64193e7be33112346207d2f2588e`。本地合并基础是 `H` 的 `f76932efe432d6d10c7707bf20e09c6a7d366e3a`。

JY 是现有 H 历史的祖先，直接执行 Git merge 不会恢复 JY 的页面。因此本次对照 JY 的页面结构、样式及交互，将它们移植到现有 React 组件，并接回本地服务；没有把 Vue 外壳或原版 `innerHTML` 路由混入 React。

## 取舍

| 部分       | 合并结果                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| 框架       | React 18、TypeScript、函数组件与 Hooks、Tailwind、pnpm、Vitest                                                       |
| 页面外壳   | JY 的 430px 居中 App 布局、米白／砖红／金色、顶部栏、五项底部导航；桌面也保留 App 形态                               |
| 页面与交互 | JY 运势、选问题、情况选择、聊聊、专题方案、人生报告、七步陪伴、今日陪伴、好物、我的、分享及提醒预览                  |
| 语言       | 保留本地首次语言弹窗、四种语言、全局切换、记忆选择和“我的”入口；补齐新增页面文案                                     |
| Logo       | 保留本地原创莲花星芒和四语言品牌名                                                                                   |
| 出生资料   | 保留本地日期／时间／城市／时区滚轮、公历佛历、未知时间与取消机制；生日必填，具体时间与城市选填                       |
| 排盘与运势 | 保留实际泰式计算；采用 JY 的页面组织，不采用原版未计算的西洋月亮／上升或固定运势充当个人结果                         |
| 聊天       | 保留本地 SSE、Qwen／Kimi 协作、Roxy 流程适配、账号档案、确认记忆、对话回顾与依据记录；原版预设聊天文本不充当 AI 回复 |

## 与本地 GitHub 和模型能力衔接

1. `kongesque/thai-astrology`：继续使用固定依赖 `thai-astrology@0.3.2` 的สุริยยาตร์计算。数据不足时保留未知范围，不假定出生时分、地点或上升。
2. `RoxyAPI/ai-spiritual-companion`：继续使用固定提交移植的温和角色、回答前回顾／成功后记录、检索回退及限额流程；归属和 MIT 许可证保留。使用现有 FastAPI／SQLite，不需要 Roxy 的收费 API。
3. Qwen 与 Kimi：`companion` 模式按同一份账号生辰、计算结果、确认记忆和当前问题起草与复核；最终只保存一条完整回答。实际执行模型与回退原因可在回答依据查看。
4. JY 情况与偏好：发送前等待当前账号保存完成。服务端读取选中的问题／情况、关注主题、心情、心愿与外观偏好，作为当前上下文；外观偏好不是占星事实，模拟订单不进入真实购买记录。

访客情况只在其点击“登录继续聊天”后带到正在登录的账号，不自动复制心愿、订单或其他私人状态。切换账号清空聊天预填和待接续状态。新增好物偏好、体验订单存入已有 `/api/companion` 的账号 JSON，旧记录会补默认值，无需数据库破坏性迁移。

## 实际服务与演示边界

- 已连接：泰式排盘、生日简版与精确资料三周期运势、账号生辰、聊天与确认记忆、陪伴状态、语言和偏好持久保存。
- 资料待补全的命盘页展示泰式结构示意，明确标注尚无个人星位；补充出生时分与地点后生成实际命盘，也可直接进入独立教学示例。
- 个人大圆盘支持圆环视图与传统泰式盘切换。星位、落宫和连线均读取该用户的泰式计算，点击点或线可核对生辰来源；八字四柱作为独立体系保留。
- 编辑内容：行动路径、长篇报告、七步练习、作息与配色。页面保留内容性质提示，不宣称它们由上游引擎直接推算。
- 演示服务：商品与报告结算、订单、预约和提醒；不扣款、不发货、不向 LINE 推送。
- 本地现有 Qwen 配置可调用。Kimi 配置保留，但账号当前模型权限不足，实际请求返回 404；这时显示 Qwen 单模型结果，不声称完成双模型复核。
- 正式 LINE 身份认证、支付、推送、多实例部署和容量验证仍需另行接入。当前本地账号仅用于开发。

## 手动验收

1. 新浏览器打开应用，确认四语言弹窗和本地 Logo；选择后进入生日滚轮，未填写时按钮不可提交。
2. 只填生日，查看今日／本周／本月，展开依据；补齐时分、城市后检查泰式本命盘和行运。
3. 在聊聊选择一个问题和情况 B，进入方案，确认试读与情况 B 对应；返回、刷新后选择保留。
4. 访客输入问题后登录或注册，确认生辰绑定后回到聊天，问题草稿和所选情况保留；发送后检查回复依据与实际模型流程。
5. 保存、修改与删除确认记忆；退出再登录，检查恢复和另一账号隔离。
6. 好物选择风格、预算、规格及数量，完成模拟结算；刷新体验记录，确认数量与总额保留。
7. 我的页面保存心愿并切换语言，刷新后验证；检查七步暂停／撤销／重启和分享 PNG。

自动化检查结果及实测限制见 [VALIDATION.md](VALIDATION.md)。计算一致性检查不能作为未来事件预测准确率或用户满意度。
