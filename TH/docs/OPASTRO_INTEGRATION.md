# OpAstro 与泰式运势适配

接入日期：2026-11-06。本次接入免费开源部分，不需要 RoxyAPI 或 OpAstro 的付费内容包。

同日追加性能优化：生成器v3实测写作阶段约10～13秒，中文日运／泰语周运相比原版约快40%，继续使用Qwen Plus。新增30秒计算复用与紧凑的模型通信格式，详见 [FORTUNE_PERFORMANCE.md](FORTUNE_PERFORMANCE.md)。下文的16～24秒为首次接入时的历史实测。

## 实际接入范围

计算仍由 `thai-astrology@0.3.2` 的สุริยยาตร์引擎完成。本命上升、星体、整星座宫制、分盘、ทักษา和泰历不切换成西洋星历。八字仍是独立工具。

从 [OpAstro 固定提交](https://github.com/dakidarts/opastro/tree/49276a01831060283f7a991218287e4bc72538e0) 的 `aggregation.py` 提取了事件重要性、星体主题权重、事件签名、排序、去重和时间窗口聚合函数。源码位于 `backend/vendor/opastro/`，版本0.1.9；`UPSTREAM.json` 记录来源、SHA256和改动，MIT许可同时位于该目录及 `public/licenses/opastro-MIT.txt`。提取的函数和常量保持原文，本地提供最小数据类型。

适配层 `backend/app/opastro_adapter.py` 用泰式原始取样生成停留、换座范围、按星座关系的连线等因素，再调用上述函数筛选重点。家庭主题、快慢星体周期权重、相对位置的生活象征属于 WANJAI 的版本化编辑规则，不冒充上游的泰国老师解读库。没有运行其 Swiss Ephemeris、默认中午生时、西洋精确相位或收费叙述包；不将泰式计都映射成西洋南交点。

## 三周期行为

| 周期 | 报告计算取样，均为曼谷时间            | 文字侧重                                   | 有效期         |
| ---- | ------------------------------------- | ------------------------------------------ | -------------- |
| 今日 | 当天00:00、06:00、12:00、18:00、23:59 | 当日节奏与较快星体的变化                   | 下一个曼谷午夜 |
| 本周 | 周一至周日，每天12:00                 | 周初／周中／周末及实际换座或持续关系       | 下周一午夜     |
| 本月 | 当月每天12:00                         | 太阳、火星、木星、土星等整月主线与阶段变化 | 下月一日午夜   |

原有四主题分类和当前分钟的日运快照保留；报告分析使用独立的固定周期取样。界面分别标明，两者不会被说成同一取样方式。换座只确定发生在相邻取样之间，不声称精确时刻；连线只在所列日期被观测到，不据首尾日期宣称全程持续。

生日必填，时间、城市选填。完整资料使用上升与整星座宫；不完整资料仅用实际泰式太阳参考，跨界时保留两种可能，不推测生时、上升或本命宫。同一太阳／上升参考可能得到相近倾向，不为制造差异伪造星象。

## Qwen 输出与失败处理

`POST /api/fortune` 先返回计算结果、OpAstro筛选因素与参考解读，有缓存时直接返回已生成的文字。前端随后按需调用 `POST /api/fortune/narrative`，后端重新计算依据，不接受客户端自造的星象。

默认用已有百炼Qwen配置，`FORTUNE_PROVIDER=qwen`。调用采用 [百炼 JSON Object 模式](https://help.aliyun.com/zh/model-studio/qwen-structured-output)、关闭思考、限制输出及总等待时长。已有其他提供商可通过此配置选择，实际兼容性需分别联调；本轮真实验证的是Qwen。

生成内容包含寄语、日／周／月段落及感情、金钱、家庭、工作四项解释和建议。每段和每个主题须引用本次真实因素编号；后端校验结构、编号、主题覆盖、基本语言和格式。

真实样例发现：只检查引用编号仍无法阻止模型复述错误宫位。因此最终版本把**星体、星座、宫位、日期和时间交给程序直接呈现**；模型只写生活层面的象征解读和建议，并检查常见四语言星体、星座、宫位词与数字，拒绝在生成正文里重新叙述计算。页面每段上方的依据来自真实计算，不由模型生成。词汇检查不是完整语义验证；解释质量和文化适配仍需人工评估。

未配置模型、超时、上游错误、输出不完整、引用或结构不合格、额度不足时，继续显示明确标注的参考解读与重试入口。不会将失败包装成AI回答。今日陪伴、专题方案和模拟解锁报告不在本次生成范围。

“聊聊这份运势”读取同账号、同生辰、同语言及周期的已缓存解读与相同因素。没有缓存时使用参考解读，聊天中不额外触发免费报告生成。原有 Roxy 开源移植的角色、记忆、召回和 Qwen／Kimi 聊天协作保留；本轮没有解决 Kimi 当前模型404权限问题。

## 多用户、隐私与费用

SQLite 持久缓存按账号、生日／生时／地点标识、语言、周期、引擎／规则／适配器／生成器版本和模型隔离。匿名缓存按连接IP摘要及出生资料指纹区分，不把访客资料绑定到账号。缓存不保存原始生日、姓名或城市文本；发送给报告模型的是计算因素与精度标记，不含原始生日、姓名、城市文本、聊天记录或记忆。

刷新不改变同一周期报告。修改生辰、语言、模型或计算版本会更换缓存键；前端取消旧请求，核对周期、日期及依据签名。曼谷换日自动重取；周、月报告在完整周期内复用，避免每天随机重写。SQLite 原子租约合并并发相同请求，旧租约不能覆盖新结果；失败冷却45秒，缓存命中不重复扣生成额度。

默认每账号／匿名IP范围每分钟3次、滚动24小时12次；同IP总计每分钟15次、滚动24小时120次，失败的付费尝试也计数。环境变量 `FORTUNE_REPORTS_PER_MINUTE`、`FORTUNE_REPORTS_PER_DAY`、`FORTUNE_NETWORK_REPORTS_PER_DAY` 可调整，设0可停止新生成。报告与聊天共享4个模型并发槽。单次报告上游HTTP超时27秒，含排队的总等待32秒。

当前仍是本地开发账号。生产身份认证、可信反向代理IP识别、分布式配额、正式数据保留／账号删除策略需要在公开多用户上线前完成；没有部署或开通任何付费服务。

## 验证方法与边界

```powershell
pnpm test
pnpm test:api
pnpm check:api
pnpm build
pnpm exec playwright test e2e/fortune.spec.ts e2e/fortune-ai.spec.ts e2e/thai.spec.ts
```

后端测试覆盖上游参考排序、泰式因素、日周月取样、未知资料、跨界、缓存身份、午夜到期、并发租约、账户／网络额度、格式与引用校验、超时降级和私密数据不进入报告请求。Hook测试覆盖延迟回答、切换周期／账号／生日／语言、失败及重试。浏览器测试使用清空真实模型密钥的独立端口，AI界面流程使用明确的拦截样例；真实模型冒烟独立使用合成档案。

本轮最终Qwen样例：中文日／周／月、泰语日、越南语周、英语月共6份均实际生成并通过结构与依据校验，耗时约16～24秒，抽查了不同周期正文。格式、计算一致性和生成成功率不等于未来事件预测准确率；本次没有经验证的泰式专家规则库，也没有开展用户满意度或预测效果研究。

重启后的实际服务另验证了仅填写生日、太阳双参考的匿名档案：成功生成解读，刷新命中同一缓存，没有补造上升或本命宫；同账号缓存能进入聊天、其他账号不能读取的流程也通过独立测试。
