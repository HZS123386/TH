# “聊聊”接入与多用户验证

记录日期：2026-11-05。当前方案使用MIT开源代码与本地泰式计算，不调用RoxyAPI商业排盘接口，不需要RoxyAPI订阅或密钥。聊天由用户配置的模型服务生成。

## 如何让回答更贴合用户

每轮读取当前账号保存的出生资料、已经选择的关心事项和情况、最近12条消息、最多20条确认笔记，以及召回的3份旧对话。当前问题明确点名今日／本周／本月时优先采用问题中的周期，否则使用界面所选周期；同时提到多个周期时最多计算这3项。没有周期请求或选择时不额外生成周期结果。

模型收到实际泰式本命、所需行运或周期规则结果，缺时分地点时保留未知。日周月简版的太阳参考不当成上升或本命宫位。提示词要求先回应生活问题，挑相关事实，给一个能执行的小步骤；不得虚构记忆、宗教背书或命运保证。旧Assistant回答是历史解读，不是用户事实；当前确认笔记优先。其他人的生辰不能拿账号本人的资料替代。

## Qwen与Kimi协作回答

本地默认改为 `DEFAULT_PROVIDER=companion`，前端显示随语言切换的“陪伴助手 · 协作模式”。`backend/app/companion_models.py`在同一套Roxy适配的召回、档案与工具流程之后运行：Qwen起草完整回答，再由Kimi依据同一份生辰、确认笔记、对话摘录、当前问题与计算结果校对润色。初稿作为不可信参考数据传入，不能成为新的事实或指令来源；最后只输出一条完整回答，不把两段回答拼接，也不保存内部初稿。

Kimi复核失败、超时或返回不完整文本时，丢弃其候选内容，保留完整Qwen回答。Qwen失败而Kimi可用时，由Kimi直接回答；两者失败则返回错误，不创建成功对话或记忆。单个模型阶段最多22秒，原有50秒总生成上限和4路并发限制仍生效。两阶段完成后才向客户端发送最终内容，因此协作模式的首字等待比单模型更长，正常情况下每轮有两次模型请求和相应费用。

Kimi鉴权／权限／型号错误暂停自动尝试5分钟，其他失败暂停30秒，冷却后再探测；状态仅在单进程内共享，不保存任何用户内容。它避免每轮重复调用已知不可用接口，不保证多实例服务的共享熔断。手动选择Qwen、Kimi等单模型时保留原来的直接流式与错误处理。

每个成功回复的 `evidence.generation` 记录实际执行模型、步骤状态、最终回答来源与 `reviewed`；“本轮参考了什么”如实显示双模型校对或单模型回答，刷新后仍保留。只有两阶段都完成才标记双模型复核。协作模式会向两家配置的服务发送相关资料，并把Qwen初稿交给Kimi，四语言隐私说明已补充。

用户可以从自己的聊天气泡点“记住这件事”，修改内容后确认，避免自动把AI解读写成个人事实。“我记得的事”和“我的记忆”提供查看、修改、删除。聊天记录与确认笔记分开删除；若要清除旧对话对后续回顾的影响，需要清空对话，删除笔记本身不会抹掉曾经说过的历史文字。

“本轮参考了什么”显示出生资料版本、计算时间、涉及周期、日期范围和回忆方式。来源随成功回复保存，重新登录仍能查看。模型中断、超时、取消或不完整回复不会保存成成功对话。

## 记忆与多用户边界

- 确认笔记最多20条，每条500字；对话档案在SQLite中持久保存。检索最多考察该账号最近200份成功回复档案，召回3份，传给模型的单份摘录最多900字符。
- 可选向量服务使用OpenAI兼容 `/embeddings`。归一化并验证非空、有限数值与最多4096维；本地按余弦相似度排序，不需要pgvector。未配置时按日期召回，未索引或服务故障时明确回退，不阻断回答。
- 只对当前会话解析出的用户ID查询。接口不接受客户端指定另一个用户；修改／删除他人笔记返回404。向量查询先按用户限定档案，当前选中情况也从本人的陪伴状态读取。
- 向量端点与模型签名变化后不复用旧索引；可从已有记录重新建立。本版不自动全库回填旧索引，未索引的旧记录只能在按日期回顾中出现。
- 清空历史、修改生辰时，成功对话依据和向量索引随外键级联删除，确认笔记保留。异步索引完成较晚时有存在性检查，不能恢复已删除记录。
- 每个账号的并发锁在等待工具前获取；本机同时最多4路模型、2路泰式计算、2路向量请求。按用户额度通过数据库事务计数，重启或多次创建Storage实例不能绕过。

这些边界验证了本地多账号隔离；没有做正式身份认证、多实例锁、负载均衡或容量压测。本地账号在production模式仍关闭。面向真实多用户上线前需接入正式认证、迁移生产数据库并补跨实例锁与容量测试，不能把本机并发测试当成可承载任意用户数量的保证。

## 百炼模型与配置

推荐候选：`qwen3.7-plus`。百炼官方定位为性能、速度和成本均衡；普通陪伴对话设置 `enable_thinking=false` 并流式输出。它是否最符合泰语用户习惯，仍需实际盲评。模型说明：[百炼模型选择](https://help.aliyun.com/zh/model-studio/models)、[思考模式](https://help.aliyun.com/zh/model-studio/deep-thinking)。

仓库的 `.env.example` 不含密钥；本地 `.env` 不在Git中跟踪。新环境按实际百炼地域填写：

```dotenv
DEFAULT_PROVIDER=companion
QWEN_API_KEY=你的百炼密钥
QWEN_BASE_URL=https://你的业务空间ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen3.7-plus
```

若使用北京旧地址 `https://dashscope.aliyuncs.com/compatible-mode/v1`，官方目前仍支持；本地模板暂用这个地址。新加坡等地域必须改成该地域的地址与密钥，不能混用。[百炼官方兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)说明了业务空间域名与地域绑定。

其他接口使用 `OPENAI_*`、`DEEPSEEK_*`、`KIMI_*` 的API_KEY、BASE_URL和MODEL。Kimi默认中国官方地址；K3系列使用低推理强度和max_completion_tokens，K2.6关闭思考；历史最终回答作为带角色的参考数据传入，避免跨模型切换时伪造或泄露保留推理。只展示content，不展示reasoning_content。未配置的单模型选项禁用；协作模式有明确记录的回退，单模型模式失败不切换。

语义检索另填 `EMBEDDING_API_KEY`、`EMBEDDING_BASE_URL`、`EMBEDDING_MODEL`，未填不影响近期对话回顾。它是额外的模型请求，有独立额度；当前没有默认启用。密钥只用于服务端，不写VITE变量，不进入页面或公开配置接口。真实模型会接收当前问题、相关档案、笔记和摘录；可选向量服务接收检索问题和被索引的对话文本，本地排盘引擎仅接收出生资料。

改完 `.env` 后重启 `pnpm dev`。本轮已在用户授权后配置百炼北京业务空间密钥、Qwen 3.7 Plus及Kimi密钥，全部仅存本地Git忽略的 `.env`。Qwen已成功真实生成泰语、中文、越南语与英语样例；首批6条中4条完成、2条上游失败，有限重试的2条均完成。未把重试样例当成首轮100%成功或稳定性保证。后续另外针对泰语和中文做提示与上下文筛选复核，去掉发给模型的内部类别代码，不把无关的本命位置混入周期行动建议。真实向量服务尚未配置，当前按日期召回。

## 如何验证“懂用户”

代码测试覆盖同时请求不同账号、不同生辰与私密笔记隔离、外账号篡改拒绝、重启续聊、语义排序、向量失败回退、删除级联和延迟索引、错误流不保存、按用户额度事务，以及真实HTTP流协议的模拟适配。它们不等于用户满意度。

评测脚本使用合成资料、独立临时数据库，输出文件在Git忽略的 `data/evals/`：

```powershell
# 默认只检查流程，不调用真实模型
node scripts/python.mjs scripts/evaluate-chat.py --provider mock
# 配置好密钥后执行，会消耗该服务额度
node scripts/python.mjs scripts/evaluate-chat.py --provider qwen
# 两模型协作及不可用时的真实回退，仍会消耗服务额度
node scripts/python.mjs scripts/evaluate-chat.py --provider companion --case th-work
```

6组样例以泰语为主，另含中文、越南语、英语，覆盖转行但不能立即辞职、分手后不急于恋爱、时间未知不许猜上升、续聊、照顾家人与关系界限。输出保留问题、确认笔记、实际回答、错误与计算依据；人工评价字段故意留空。可用重复的 `--case th-work --case zh-followup` 仅复核指定样例，减少无关调用。

请泰语母语评审按0–2分分别评价：有没有回答当前问题、是否正确使用用户提供的信息、语言是否自然、事实是否有依据、下一步是否可执行、整体是否有帮助。相同样例盲测不同模型，记录版本、延迟与成本；不要让模型自己编一个满意度分数。真实用户反馈、持续回访与隐私删除还需单独验收。当前没有宣称满意度或算命预测准确率达标。
