## 实际调整与检查

- 生辰卡、星位查询和全部解读同步显示24小时实际时间及上午／下午。时间滚轮确认前显示将保存的当地24小时值，取消不会写入。
- 两个视图明确标注共用传统泰式模型；太阳、月亮、上升标签增加“泰式”，避免被理解为回归黄道结果。
- 可展开查看输入的当地时刻、UTC、时区和实际坐标；说明整宫、按星座连线以及传统上升的精度范围。
- 服务端缓存指纹加入输入审计版本，重新计算既有缓存以补齐计算输入说明；计算公式保持原版本。
- 对本例十个星体的全部45对关系独立按星座距离核对：相隔2／10座为六合、3／9座为四方、4／8座为三方、6座为对宫。19条现有连线与分类一致，没有通过增删线条模仿手机图。
- 测试涵盖全部1440分钟的12／24小时转换、午夜／中午、无时间不伪造UTC、北京早晚输入、实际API到圆盘经度的一致性、修改／取消／保存、四语言及手机布局。

自动检查验证的是输入、算法口径、图形对应和软件行为。传统固定Anto上升在海外还需同流派独立参考盘；显示角分不表示具有相同的现代天文精度，也不表示未来事件预测准确率已验证。

## 离线复现

生产引擎仍为 `thai-astrology@0.3.2`，源码基线 `445577e7cbc8c09ddc98f2ec016cd3d1e32940fb`。

审计用Astronomy Engine包的npm shasum为 `41b9fd2afb7eba3485e3803cbd9033011f8557af`，integrity为 `sha512-8yWKNf7UeNbH458h3sAJ6ZgAjE5jTXp/mNNRFoC20j2SHwZIjAQeEsBB2Q3uCFRaTCCJRv33K2XhkhZQMXoX6w==`。

在项目根目录运行以下PowerShell命令（只解压到忽略的tmp目录，不修改package.json或锁文件）：

```powershell
New-Item -ItemType Directory -Force tmp/astronomy-audit | Out-Null
npm pack astronomy-engine@2.1.19 --pack-destination tmp --ignore-scripts
tar -xf tmp/astronomy-engine-2.1.19.tgz -C tmp/astronomy-audit
node scripts/audit-chart-inputs.mjs tmp/astronomy-audit/package/esm/astronomy.js
```

原始数值写入 `tmp/chart-input-audit.json`。太阳／月亮为地心视位置，几何上升按真黄道日期坐标与地平线求交，未使用折射或普拉西度斯宫头。
