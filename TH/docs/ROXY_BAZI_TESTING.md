# Roxy八字接入与测试页面

八字页面现为 `/tools/bazi`，保留在探索模块的八字入口。原 `/bazi-test` 及右上角菜单、“我的”的主要测算入口已按后续需求改为泰式占星，见 [THAI_READING_TESTING.md](THAI_READING_TESTING.md)。两种页面都不要求登录，不修改账号或访客档案。

## 已接入的流程

- GitHub来源为固定的 `lunar-python==1.4.8`，独立计算四柱、可见干支五行，并从已校验四柱查询日主、十神与藏干。
- Roxy来源为官方 `https://roxyapi.com/api/v2/chinese-astrology/bazi/` 下的 `chart`、`day-master`、`luck-pillars`、`annual-forecast` 四个接口。
- 页面选择生日、真实时分、时区及主题卡片后，自动使用默认测算内容。启用Roxy时默认使用Roxy；未启用时仅提供GitHub基础排盘，不显示来源选择。
- 分类先实现“中国占星”，包含八字排盘、全年运势、财运、婚恋、事业和家庭六个入口。排盘和个人主题默认计算四柱及日主强弱；全年运势默认计算四柱及所选年份流年。页面不显示测算内容勾选，也不显示十年大运入口。
- 每次先独立核对GitHub与Roxy四柱。主题报告使用已核对四柱、GitHub历法表给出的日主／十神／藏干，以及Roxy实际返回的强弱或流年；不再把同一份Roxy通用摘要复制到各卡片。
- 现有模型按所选主题撰写“对你的解读、优势与需要留意的地方、针对你的建议”。每段关联实际存在的命盘信息；具体干支、日主、十神、分数和年份由程序直接呈现，模型只写生活层面的解释与建议。没有“把解读放回生活”、编辑提示或“阅读范围”段落。
- 全部界面、事实、正文、建议与下载报告跟随zh/en/th/vi系统语言。已知强弱因素使用保留数值的固定翻译；其它必要文本由报告生成一并翻译，并校验语言与数字。不直接展示外语原文作为目标语言报告。
- “保存报告”下载独立HTML，包含出生资料、四柱、可读的结构化测算结果与解读，可在浏览器中打印或保存为PDF。页面及导出均不包含原始JSON与计算依据入口。
- 启用 `BAZI_PROVIDER=roxy` 后，新保存档案及明确询问八字的聊天使用Roxy计算。已有历史档案保留原来源标识；测试页始终重新按所选资料计算。GitHub引擎作为用户要求的独立对照保留。
- 泰式排盘和现有泰式周期聚合继续使用原引擎。Roxy没有公开的泰式สุริยยาตร์同口径接口，不能用西洋结果替换后仍称为泰式。

## 密钥与调用范围

密钥只在被Git忽略的服务端`.env`中，变量为`ROXY_API_KEY`。`ROXY_ENABLED=true`启用服务；不要添加`VITE_`前缀。前端公共配置只返回是否启用、操作名和本地额度，不返回密钥。

每次先取得四柱，按选择增加强弱、大运和流年调用。服务端每个账号或匿名网络范围默认每分钟12次、滚动24小时80次，失败尝试同样计数。参数为`ROXY_REQUESTS_PER_MINUTE`和`ROXY_REQUESTS_PER_DAY`。相同来源、输入、语言和所有者的成功结果在当前进程内缓存24小时；并发同请求合并，失败冷却30秒。上游总等待30秒，不自动重复重试。

出生姓名和城市文本不发送Roxy；仅发送排盘所需日期、时刻、时区、固定口径及所选年份／排运公式。测试数据不会写入账号档案。原始结果为传统象征内容，不直接执行其中的HTML或指令。

主题撰写默认使用已有Qwen服务端配置，可用`BAZI_REPORT_PROVIDER`切换到已配置的模型。模型仅接收必要计算事实、所选主题与语言，不发送姓名、城市文本、完整生日、账户档案或聊天记录。未配置Roxy的本地基础模式不调用付费撰写模型。

主题报告按所有者、命盘事实、主题、语言、模型和版本隔离缓存24小时，并合并相同的并发请求。`BAZI_REPORTS_PER_MINUTE`／`BAZI_REPORTS_PER_DAY` 为正数时分别执行每分钟／24小时次数限制；0 表示该项不限次数。当前测试配置两项均为0。每份最多进行一次正文修复，即最多两次模型调用；只有返回了候选正文但未通过语言、结构或事实约束时才修复，不对网络、授权或限额错误自动重试。总等待上限95秒，失败冷却20秒，错误不会被包装成通用解读；页面和下载均保留未完成状态。

服务端先解析出生地时区，再把所选时钟的完整时分秒与当时实际UTC偏移发送Roxy，保留夏令时折返和历史秒级偏移。立春与节气的年／月界按同一实际时刻在固定UTC+08:00下核对；日／时柱按页面选择的民用时钟计算。

## 如何测计算是否正确

1. 使用下方`pnpm verify:roxy --live --case standard`脚本运行双源对照；来源选择已从用户页面移除。两边固定立春年界、split-zi日界、民用时间。可选出生地当地时钟，或把两边共同换算到北京时间。旧项目默认八字口径是北京时间，这与Roxy默认读取当地时钟不同，不能混着比较。
2. 固定例：公历1995-08-17、10:30、Asia/Shanghai，已知四柱为乙亥／甲申／庚辰／辛巳。核对四柱、原始返回及同一生辰回显。五行只比较可见干支计数，不把数量说成喜用神。
3. 增加23:00附近、立春和节气附近的样例。1990-06-15、23:30、Asia/Shanghai的split-zi口径，可核对日柱辛亥与时柱庚子。时刻必须固定到分钟；不允许为得到一致结果而事后改口径。
4. 用同一时刻在曼谷与上海的表示核对“换算为北京时间”路径。测试夏令时重复或不存在的时刻，应在本地拒绝，不接受上游静默挪时。
5. 再找同流派独立历书或老师给出的参考结果。两个软件一致是“一致性检查”，并不能单独证明计算绝对正确。保留不一致样例和口径。

## 如何测解读有没有依据

强弱、大运、流年的页面会列实际返回及计算因素。本地当前没有这些项目的独立计算器，因此不提供它们的对照通过率。

强弱分数是三项贡献值的代数和，可以为负数，不是百分制。接口按分数分为极弱、偏弱、平衡、偏强和极强五档；适配器核对三项求和与档位，不能将“极强”误显示为“偏弱”。

请评审逐条检查：是否引用了实际返回的日主／十神／强弱因素；年份是否在所选范围内；有没有从五行数量直接编出喜用神；是否把规则分数当成事件成功概率；建议是否对应所选主题与已返回因素。相同生辰切换事业、财运、婚恋、家庭时，计算事实可以相同，但解释重点和行动建议应不同。不同生辰只有在命盘事实确有变化时才要求解释随之变化，不能为了制造差异而虚构结果。四种语言分别核对；自动脚本检查不能代替语义和流派评审。

如果要评估未来事件预测，需预先写明可观察事件、时间范围、基准和失败条件，用未参与调参的新样本前瞻记录。满意度、排盘一致、接口200和格式通过都不能当作未来预测准确率。当前不报告这类准确率。

## 自动化与真实验收

```powershell
pnpm test
pnpm test:api
pnpm check:api
pnpm build
pnpm exec playwright test e2e/bazi-test.spec.ts
node scripts/python.mjs -m pytest backend/tests/test_bazi_reports.py -q

# 不调用Roxy，只运行本地合成样例
pnpm verify:roxy

# 会使用接口额度，仅传合成资料
pnpm verify:roxy --live --case standard --all-topics
pnpm verify:roxy --live --case late-zi
```

真实验收结果保存在Git忽略的`data/roxy-evals/`，含输入、实际返回、对照与报告，不含密钥。自动化浏览器和后端测试清空真实密钥，使用明确的拦截样例；不能把这些拦截样例计入真实服务成功率。

本次真实验收：标准样例的四柱、日主强弱、大运、流年四个接口均成功返回；标准、晚子时、跨时区三个样例的四柱均与本地计算一致。记录见`bazi-live-20261107-160154.json`与`bazi-live-20261107-161038.json`。这只是三个合成样例的计算一致性记录，不代表解读或预测准确率。

主题报告本轮验收记录为`bazi-reading-20261107-174609.json`：六类中文主题、英／泰／越语事业主题及第二生辰，共10个合成组合均生成成功；六类正文各不相同，第二生辰的命盘与事业正文发生对应变化。早期语言／约束失败记录仍保留，未计为成功报告。运行页面另经实际HTTP验证，泰语财运请求返回`ready`，记录为`bazi-http-readiness-th.json`。

当前自动化验收为66项前端、202项后端和12项电脑／手机浏览器测试通过，生产构建通过。它们验证功能、输入隔离、字段引用、语言、错误处理与导出，不是未来事件预测准确率。
