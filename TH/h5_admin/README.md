# H5 运营后台

日期：2026-11-14

2026-11-15 已统一整理到独立目录 `TH/h5_admin/`：`web/` 是页面，`service.py` 是管理接口，`tests/` 是后台测试，`docs/` 保存验收报告和截图。

目标：在现有 H5 与共用后端内提供简洁的中文管理界面，按业务归类，说明数据来源，定位失败和卡点。

## 已明确的需求

- 用户要求：“UI简洁，数据清晰，知道所有数据的来源，失败这些。数据要进行归类”。
- 唯一开发、启动目录为“海外-玄学”，复用现有数据库与业务调用链。
- 保留支付核验与报告解锁规则；后台统计必须区分已解锁和已核验支付。
- 不触碰其他正在进行的 App 修改；测试不创建真实支付订单、不付款。
- UI 参考：[Shadcn Admin](https://github.com/satnaing/shadcn-admin)、[Tabler](https://tabler.io/)，采用浅色侧栏、指标卡、筛选明细表的布局。

## 范围确认

- 问：第一版仅查看与排查，还是也需要业务操作？用户答：“这两个都需要”。
- 第一版同时提供查看、筛选、来源追溯、异常定位，以及重新核对到账、重试失败报告、异常备注与处理进度。
- 业务操作直接调用现有支付核验、报告生成服务，记录管理员、时间、目标、结果；不增加直接免费解锁、代付或重复建单能力。
- 管理页面接入现有 FastAPI 工厂的 `/admin/`，使用同一数据库和启动命令。

## 数据口径与实现

| 分类 | 来源 | 口径 |
| --- | --- | --- |
| 访问与来源 | `landing_visits`、`landing_visitors`、`landing_visit_reports` | 访客编号按匿名浏览器保存，格式为地区、首次记录日期（北京时间）、序号。首次访问链接的 `utm_region` 是地区标签，缺少时显示「未知」。渠道取 `utm_source` 和 `utm_campaign`。访问记录和不再活跃的访客编号随 30 天保留期清理。 |
| 报告 | `life_reports` | 按报告创建时间筛选，显示当前预览、完整报告、权限和生成状态。生成租约过期单独标为中断。 |
| 订单与实收 | `life_card_payments` | 按订单创建时间；旧单没有时间则用报告创建时间。正式网关、`PAID`、服务端确认凭据与本单网关/单号一致，才计入实收。模拟、沙箱、未核验分开。 |
| 模型调用 | `report_model_usage` | 仅查询关联 H5 报告的调用。Token 使用上游返回值；调用失败可能在后续恢复。旧数据没有耗时或错误码时显示历史未记录。 |
| 接口失败 | `h5_request_failures` | 从本次功能启用起记录 H5 API 非成功响应，含报告创建前的失败、请求过大及限流。保留 30 天、最多 20000 条；不保存请求体、IP、密钥或查询参数。 |
| 内部跟进 | `admin_cases`、`admin_audit` | 待处理、跟进中、已处理仅表示管理员跟进进度；不改变业务支付状态。记录动作、管理员、目标、原因和结果。 |

新报告保存创建时的访客编号，以及该编号首次入站记录的渠道、活动和投放地区。报告复用、生成重试和访问过期后仍使用已保存的值。历史未知来源继续显示未归因。总览同时展示按浏览器去重的访问人数和按访问统计的转化。可用访客编号查询访问、报告、订单、模型调用、异常与操作记录，当前页导出也包含该编号。

所有页面按北京时间展示。时间选择筛选各类记录的创建时间，业务状态反映查询时的当前状态；不是指定日期的历史状态快照。趋势图最多显示最近 30 天。CSV 只导出当前页，金额、时间字段注明单位，文本做公式注入防护。

## 页面与业务操作

- `/admin/`：数据总览、访问与来源、报告、订单支付、模型调用、失败异常、管理员操作记录、数据来源口径。
- 搜索、状态、来源、异常分类、处理进度筛选；分页；当前页 CSV 导出；访问与失败记录可进入关联报告详情。
- 核对到账：只查询已有 Sunlands 订单，调用原 `confirm_card_order` → `confirm_sunlands` → 原报告生成流程；不会创建订单或代付。结果不确定、凭据不匹配时按原规则拒绝。
- 重试报告：免费预览复用原快照和生成租约；完整报告必须已经解锁，复用原分章生成流程。会消耗配置的模型服务用量，执行前要求填写原因。
- 添加处理记录：保存备注与内部跟进状态，保留操作历史；已完成或正在生成的报告不会被后台重新覆盖。
- 请求 ID 防止重复提交同一个操作，操作异常也记录结果码。若网络中断，请先刷新详情查看业务状态与记录，再决定是否重试。

后台模块由 `TH/backend/app/main.py:create_app` 注册，共用原服务进程。静态管理页面在 `TH/h5_admin/web/`，管理接口在 `TH/h5_admin/service.py`。订单和报告使用 `TH/.env` 的 `DATABASE_URL` 指定的 PostgreSQL。

## 启动与管理员配置

在仓库根目录运行原命令：

```powershell
node TH/scripts/dev.mjs --skip-build
```

打开 `http://127.0.0.1:8000/admin/`。后台与 H5/App 共用当前数据库，不需要构建 Flutter 或启动另一套服务；`--skip-build` 仅适用于已有 H5/App 构建。

本机已配置管理员，登录信息保存在 `TH/data/admin-access.txt`（Git 忽略）。配置项位于 `TH/.env`：

```dotenv
ADMIN_USERNAME=你的管理员账号
ADMIN_PASSWORD_HASH='生成的 scrypt-v1 密码哈希'
```

新环境可在 `TH` 目录通过原账户密码模块生成哈希：

```powershell
.\.venv\Scripts\python.exe -c "from getpass import getpass; from backend.app.accounts import password_hash; print(password_hash(getpass('Admin password: ')))"
```

填写配置后重启服务。修改账号或密码哈希会使旧会话失效。未配置时数据接口关闭；没有公共默认密码。会话有效期 8 小时，使用 HttpOnly、SameSite=Strict Cookie，生产模式要求 HTTPS Secure Cookie。写操作校验来源与 CSRF；登录失败按网络限流。页面和接口禁止缓存、禁止嵌入第三方框架。

本地开发环境中已有真实订单记录，不应因为界面标为“本地开发环境”就认为所有订单都是测试单。订单环境逐条按支付网关和商户类型判断。
