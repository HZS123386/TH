# H5 运营后台

日期：2026-11-14

2026-11-15 已统一整理到独立目录 `TH/h5_admin/`：`web/` 是页面，`service.py` 是管理接口，`tests/` 是后台测试，`docs/` 保存验收报告和截图。

目标：在现有 H5 与共用后端内提供简洁的中文管理界面，按业务归类，说明数据来源，定位失败和卡点。

## 已明确的需求

- 用户要求：“UI简洁，数据清晰，知道所有数据的来源，失败这些。数据要进行归类”。
- 唯一开发、启动目录为“海外-玄学”，复用现有数据库与业务调用链。
- 保留支付核验与报告解锁规则；后台统计必须区分已解锁和已核验支付。
- 不触碰其他正在进行的 App 修改；测试不创建真实支付订单、不付款。
- UI 参考：[Shadcn Admin](https://github.com/satnaing/shadcn-admin)、[Tabler](https://tabler.io/)，采用浅色侧栏、指标卡、筛选明细表的布局。

## 范围确认

- 问：第一版仅查看与排查，还是也需要业务操作？用户答：“这两个都需要”。
- 第一版同时提供查看、筛选、来源追溯、异常定位，以及重新核对到账、重试失败报告、异常备注与处理进度。
- 业务操作直接调用现有支付核验、报告生成服务，记录管理员、时间、目标、结果；不增加直接免费解锁、代付或重复建单能力。
- 管理页面接入现有 FastAPI 工厂的 `/admin/`，使用同一数据库和启动命令。

## 数据口径与实现

| 分类 | 来源 | 口径 |
| --- | --- | --- |
| 访问与来源 | `landing_visits`、`landing_visitors`、`landing_visit_reports` | HTML 欢迎页可见时先记录访问，Flutter 接管后沿用该编号。新打开入口以当前链接的 UTM 记录新访问，刷新和历史返回恢复原访问。访客按匿名浏览器去重，地区来自 `utm_region`。访问和不再活跃的访客编号按 30 天保留期清理。 |
| 报告 | `life_reports` | 按报告创建时间筛选，显示当前预览、完整报告、权限和生成状态。生成租约过期单独标为中断。 |
| 订单与实收 | `life_card_payments` | 建单量按订单创建时间统计，历史缺少建单时间时使用报告创建时间。核验实收按服务端核验通过时间统计，只累计凭据与本单匹配的正式到账订单。历史缺核验时间的已核验订单可在「全部记录」下查看。 |
| 建单来源 | `life_card_payments.landing_*` | 首次写入订单时按报告归属核对本次访问，保存访问编号和渠道、活动、投放地区。报告首次来源使用报告快照。历史订单缺建单来源时显示「未归因」。 |
| 模型调用 | `report_model_usage` | 仅查询关联 H5 报告的调用。Token 使用上游返回值；调用失败可能在后续恢复。旧数据没有耗时或错误码时显示历史未记录。 |
| 接口失败 | `h5_request_failures` | 从本次功能启用起记录 H5 API 非成功响应，含报告创建前的失败、请求过大及限流。保留 30 天、最多 20000 条；不保存请求体、IP、密钥或查询参数。 |
| 内部跟进 | `admin_cases`、`admin_audit` | 待处理、跟进中、已处理仅表示管理员跟进进度；不改变业务支付状态。记录动作、管理员、目标、原因和结果。 |

新报告保存创建时的访客编号，以及该编号首次入站记录的渠道、活动和投放地区。报告复用、生成重试和访问过期后仍使用已保存的值。历史未知来源继续显示未归因。总览同时展示按浏览器去重的访问人数和按访问统计的转化。可用访客编号查询访问、报告、订单、模型调用、异常与操作记录，当前页导出也包含该编号。

所有页面按北京时间展示。查询范围按各类记录的创建时间或核验时间筛选，业务状态反映查询时的当前状态。趋势图最多显示最近 30 天。CSV 只导出当前页，金额、时间字段注明单位，文本做公式注入防护。

## 页面与业务操作

- `/admin/`：数据总览、访问与来源、报告、订单支付、模型调用、失败异常、管理员操作记录、数据来源口径。
- 搜索、状态、来源、异常分类、处理进度筛选；分页；当前页 CSV 导出；访问与失败记录可进入关联报告详情。
- 访问明细增加最后页面、最后操作和最后记录时间，CSV 同步导出。覆盖欢迎页、资料填写、数据确认、历史列表、隐私/帮助、报告生成/加载/预览/完整内容及支付弹窗；支付可区分建单、发起打开官方收银台、手动核验等事件。
- 最后记录时间为服务器收到最新事件的北京时间。页面前后台切换、离开及恢复时尽力上报；前台只是上报时可见，不保证当前在线，切到后台不等于放弃。离开事件无法区分关闭、刷新或跳转，外部收银台内部不可观测，成功页面事件不替代服务端到账核验。断网、浏览器关闭及隐私设置会造成漏报，历史缺失显示“未采集”；不回填猜测的离开位置或原因。
- 核对到账：只查询已有 Sunlands 订单，调用原 `confirm_card_order` → `confirm_sunlands` → 原报告生成流程；不会创建订单或代付。结果不确定、凭据不匹配时按原规则拒绝。
- 重试报告：免费预览复用原快照和生成租约；历史已解锁报告复用原分章生成流程。LINE 报告从「LINE 报告发放」页面重试。会消耗配置的模型服务用量，执行前要求填写原因。
- 添加处理记录：保存备注与内部跟进状态，保留操作历史；已完成或正在生成的报告不会被后台重新覆盖。
- 请求 ID 防止重复提交同一个操作，操作异常也记录结果码。若网络中断，请先刷新详情查看业务状态与记录，再决定是否重试。

后台模块由 `TH/backend/app/main.py:create_app` 注册，共用原服务进程。静态管理页面在 `TH/h5_admin/web/`，管理接口在 `TH/h5_admin/service.py`。订单和报告使用 `TH/.env` 的 `DATABASE_URL` 指定的 PostgreSQL。

## 启动与管理员配置

更新后启动前在 `TH/` 执行现有迁移命令 `node scripts/python.mjs -m alembic -c backend/alembic.ini upgrade head`。`20261120_claim_code` 为已有报告补齐 5 位领取编号，`20261120_merge_line_reports` 合并原有 dev 与 LINE 的迁移历史。

在仓库根目录运行原命令：

```powershell
node TH/scripts/dev.mjs --skip-build
```

打开 `http://127.0.0.1:8000/admin/`。后台与 H5/App 共用当前数据库，不需要构建 Flutter 或启动另一套服务；`--skip-build` 仅适用于已有 H5/App 构建。

本机已配置管理员，登录信息保存在 `TH/data/admin-access.txt`（Git 忽略）。配置项位于 `TH/.env`：

```dotenv
ADMIN_USERNAME=你的管理员账号
ADMIN_PASSWORD_HASH='生成的 scrypt-v1 密码哈希'
```

客服使用同一个 `/admin/` 页面登录。用不同的用户名和同一方式生成的密码哈希配置 `REPORT_SUPPORT_USERNAME`、`REPORT_SUPPORT_PASSWORD_HASH` 后重启。客服只能访问「LINE 报告发放」。在 LINE 收到五位领取编号后，输入编号查询并点击「确认已加好友」。后台生成完整报告，生成完成后可「下载 PDF」。客服在 LINE 发送后点击「标记已发送」。领取码用于客服查找报告，完整内容由客服发放。下载使用同服务 `/thai-landing/` 下的 H5 构建产物。

H5 用户通过 LINE 领取完整版。服务器默认关闭新建支付订单，已有订单的核对、已解锁报告及售后记录继续可用。

「领取码报告统计」按北京时间选择首次打开领取码的起止时间，支持今天、今天中午前和自定义时段。开始时间计入，结束时间作为区间边界。每份报告按首次弹码时间计一次，并显示这批报告当前的发放状态。

「待确认好友」列出打开过报告联系码、还未人工确认的报告。「待发报告」保留所有已确认但未登记发送的报告。这两个待办展示全部日期，可通过领取编号跨日期查询。总览和销售端的「已登记发送」都按登记发送时间筛选，每份报告计一次。所选日期范围也适用于「已发送」列表。点击人数按匿名浏览器去重，二维码弹出次数按二维码成功显示计数。这两项联系统计按服务端收到事件的时间计算，最多保留 30 天。

新环境可在 `TH` 目录通过原账户密码模块生成哈希：

```powershell
.\.venv\Scripts\python.exe -c "from getpass import getpass; from backend.app.accounts import password_hash; print(password_hash(getpass('Admin password: ')))"
```

填写配置后重启服务。修改账号或密码哈希会使旧会话失效。未配置时数据接口关闭；没有公共默认密码。会话有效期 8 小时，使用 HttpOnly、SameSite=Strict Cookie，生产模式要求 HTTPS Secure Cookie。写操作校验来源与 CSRF；登录失败按网络限流。页面和接口禁止缓存、禁止嵌入第三方框架。

本地开发环境中已有真实订单记录，不应因为界面标为“本地开发环境”就认为所有订单都是测试单。订单环境逐条按支付网关和商户类型判断。

## 备份与验收

### 访问轨迹、停留和失败关联

- 从“访问与来源”的“查看访问轨迹”打开详情，按顺序分页查看关键操作、页面状态变化、各页面可见停留及最近关联失败；错误记录也可跳到对应访问。
- 同一次进入页面使用独立编号，可见时长以累计最大值计入；页面切后台后暂停，返回后继续，页面切换或刷新使用新编号。每 15 秒保存检查点，重复补发不重复计时。该时长不代表阅读完成，浏览器突然结束时可能缺少最后一段。
- 复用 `/api/landing/visits` 批量上报，每批最多 20 条；按访客限流 120 请求/分钟，其他业务接口仍使用原限流。前端检查 HTTP 响应和事件确认，尊重 `Retry-After` 并退避重试，网络恢复或同标签页刷新后继续发送。
- 待发队列保存在当前标签页的 sessionStorage，绑定原浏览器所有者，最多 500 条；超过上限时保留较新记录并显示溢出数量。存储受限、关闭标签页或强制结束浏览器仍可能丢失未确认内容；不承诺完整离开证据，也不补造旧记录。隐私开关开启后清空待发队列并停止采集。
- 浏览器返回/前进恢复缓存页面时，读取该标签页最新队列，只合并本页尚未保存的新事件；成功回执按访问编号和事件序号删除对应记录，避免旧页面或晚到回执覆盖中间页面轨迹，也避免复活已确认的旧记录。存储临时受限时保留内存中的未保存变更，恢复后再合并。
- 请求携带 `X-Visit-Id`，服务端只存所有者哈希并核对归属；允许先记录失败、后关联成功补发的访问，防止报告创建前的错误丢失访客关联。地点查询纳入错误捕获；网络/超时、响应解析错误作为客户端异常单独显示，不冒充 HTTP 状态。
- 轨迹跟随访问保留 30 天，失败记录继续保留 30 天且最多 20000 条。导出新增累计可见毫秒和队列溢出数。后台仍以正式服务端支付核验决定到账，轨迹中的支付按钮操作不改变权益。
- 浏览器机制依据：[Fetch 错误响应](https://developer.mozilla.org/en-US/docs/Web/API/Window/fetch)、[keepalive 请求大小限制](https://developer.mozilla.org/en-US/docs/Web/API/RequestInit)、[页面可见状态](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)。

- 变更前数据库在线备份及原源码保存在 `D:\Backups\FATE-admin-20261114-222948`；SQLite 完整性检查通过。
- 验收使用隔离数据库和原测试替身，管理操作没有触发真实建单、付款或收费模型调用。
- 实际业务库只做后台读取、管理员会话与新增表结构初始化；业务内容与备份逐项比对，结果见验收报告。
