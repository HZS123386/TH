当前解读
两种选牌流程共用同一个解读接口。用户选好牌并确认问题后，共用 FastAPI 按原顺序查询 Roxy 的牌义，选择对应的正位或逆位，用项目现有模型结合牌位和问题写成简体中文或泰文。解读以 GitHub 上 Roxy 开源伴侣的证据优先和温和语气为基础。
浏览器只发送问题、牌阵、主题、语言和所选牌。Roxy 只接收牌名及查牌需要的语言。服务端在短时间内合并相同请求，问题和报告不写入数据库。最近 12 份报告在浏览器内保存。生成失败、刷新或切换语言后，可以用原来的问题和牌再生成。
线上入口 https://fatespread.top/ 使用同源的 /api/tarot/readings。接口使用共用服务器上的 Roxy 与报告模型配置。完整报告延续 LINE 人工领取。
本项目采用 Roxy 现有的 GET /tarot/cards/{id}，文档 https://roxyapi.com/api-reference/tarot。开源逻辑来源 https://github.com/RoxyAPI/ai-spiritual-companion/tree/3b313e6972b92aecf94dad2aecbe822e1599fa4a，其 MIT 许可在共用项目 TH/public/licenses 中。

产品交互
1. 保留问题先行、1/3/5 张匹配牌阵、动态洗牌、飞牌和翻面。
2. 报告仍为当前状态、主要阻碍、后续机会、指引与建议四部分；第一部分和所有基础牌义免费，后三部分保留具体问题、对应牌面与模糊正文预览。
3. 报告封面、章节预览、完整报告介绍卡和底部固定栏统一打开 LINE 领取面板。
4. 所有报告领取按钮统一为“点击扫码添加LINE好友领取报告”。弹窗直接显示“添加 LINE 好友”、二维码、领取编号、复制按钮和金色“打开 LINE”按钮；关闭和打开入口位于底部。取消三步列表、大文本框和折叠二维码。复制失败时才展开可手动选中的领取信息。
5. 六位领取编号由本次报告 ID 稳定生成，刷新不变，只用于人工核对，不是服务器查询码，不保证全局唯一。复制按钮下明确说明会同时复制问题与牌阵，客服收到完整消息后人工交付。复制文本包含领取编号、原问题、牌阵、每个牌位的牌名及正逆位、参考编号、生成时间、语言。问题和牌阵优先显示，方便用户检查。
6. 复制失败不显示成功，提供选中文字的手动兜底；LINE 外跳用新窗口保留报告页面。返回后可继续复制和打开 LINE。
7. 本地只记录 copiedAt 和 openedAt，不把点击当加好友、发送或报告交付成功，不自动解锁。已保存的旧完整报告继续保留；普通报告不会因点击 LINE 变为完整报告。
8. 保存文字报告和我的报告保留；之前删除的米拉陪聊区、底部说明、报告编号区和重新开始区没有恢复。
9. 中文 ?lang=zh，泰文 ?lang=th。泰语为工作稿，投放前需母语审校。

人工交付的必要说明
报告保存在用户浏览器。客服不能单凭 MIRA 编号或 #report 链接跨设备检索，因此领取消息会带齐问题与牌阵，不能只复制编号。当前没有服务器领取记录、LINE Messaging API、好友状态回调、自动发送报告或运营后台。
运营人员收到用户主动发来的咨询信息后，须根据同一问题、牌位及正逆位生成/整理完整报告，在 LINE 中发送。未来接入后端时，应先保存报告和领取码、绑定渠道、提供客服查询，再考虑按领取码自动发放；本版未伪造这些能力。
历史报告仍可读取当时保存的牌阵和基础解读。塔罗内容提供象征性的反思与行动提示。

数据与埋点
报告、草稿和复制/打开时间保存于本机，最多保留12份报告。咨询内容只由用户复制并在 LINE 主动发送；出站 LINE URL 不附带问题或牌阵。
新增本机事件：line_receive_view、line_message_copied、line_open_clicked。只带主题/牌阵类别，不记录问题、复制消息或聊天正文。点击率不是好友添加率或报告交付率，后两项需运营/服务端确认。
