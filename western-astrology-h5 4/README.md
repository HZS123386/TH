# FATE 运程解析

保留原型中的 AI 占星师形象与紫金配色。七个运程主题采用年度通栏卡片加六张双列卡片的布局，金色图标配统一底座，右上角显示锁定标识；小屏幕保留足够高度供中泰文换行，卡片间距与文字层级统一。「立即解析」按钮位于主题区域上方，保留原提交逻辑和呼吸动效；下方旧解读示例区域及其弹窗已移除。默认泰语，右上角可以切换中文。出生资料表单已接入 TH 项目的真实泰式排盘及主题解读接口。品牌标识统一为 FATE。

## 预览入口

- `/`：泰语整体星盘页（默认）
- `/?lang=th&topic=love`：泰语感情页
- `/?lang=zh&topic=love`：中文审稿版
- `/?lang=th&topic=career`：泰语事业页
- `/?lang=th&topic=life`：泰语整体星盘页
- `/?lang=zh&reading=money`：中文财富解读入口
- `/?lang=th&reading=annual`：泰语全年解读入口
- `/report.html?id=<报告编号>&lang=zh`：独立人生报告页，刷新后读取本设备的同一份报告

## 已实现

移动布局、双语切换、出生日期（阳历）与出生时间、出生地点联动选择、必填校验，以及整份《人生报告》。出生国家单独一行，下方左右分别是省份／府州、市区；三个输入框均有下拉箭头，可以点击选择或输入搜索。国家支持中国与泰国，省府目录分别包含 34 个省级地区和 77 个府级地区；市区只在选定省府内检索，上级改变后清空下级。中泰地点支持中文、泰文及英文检索，结果跟随页面语言显示；重名地点需从候选结果确认，缺少译名时使用来源名称。选择市区后采用该地点坐标及时区；选择行政区时提示采用代表坐标。表单、试读、解锁区域和完整报告沿用首屏深紫与香槟金配色。

新生成的《运程解析》使用三项免费内容、七个解锁主题和总结建议的目录：基础信息、运程摘要与个人特点免费；年度运程、整体运程、格局解读、婚姻情感、财运事业、风险提醒、姻缘及其行动建议在解锁后展示。婚姻情感侧重长期关系与共同责任，姻缘侧重吸引偏好、相识节奏和适配观察；格局是泰式本命结构的优势组合，风险提醒提供条件性的阻力与应对，不将其描述为必然灾损。每个主题使用自己的实际宫位因素和独立生成正文，年度部分使用所选年份的真实月度状态。

勾选“不记得确切时间”后仍可生成报告，提交和保存的 `birth_time` 保持 `null`。人生报告在计算环节明确按出生地当地 12:00 估算，不改变其他排盘入口的未知时间逻辑；表单、报告封面、导出文件与计算依据均提示估算及偏差。估算报告和确切 12:00 出生的报告分别保存，模型收到估算标记并按不确定信息解释；历史报告页仍显示未知时间及估算提示。

点击「立即解析」时只生成或复用免费试读，播放视频动画并显示免费内容进度；达到100%后进入独立报告页。报告正文与底部悬浮栏均提供「下载 APP 免费解读」和按报告价格「购买解析」两个按钮；APP 按钮按当前要求仅展示，不跳转、不触发网页解锁。购买按钮打开现有收银台，演示价格为运程解析 ฿50、职业专题 ฿99。默认使用银行卡演示，填入测试卡并点击「模拟支付」后调用现有解锁接口，并播放完整报告生成动画。继续链接可在当前浏览器恢复页面。已有完整内容直接复用，失败重试只补齐未完成部分。报告在 TH 后端 SQLite 中按设备随机密钥和资料版本保存，可从“我的报告”再次打开。

免费报告与解锁完整报告均播放迁移包中的视频动画，静音、循环并在手机页面内播放。免费阶段将摘要、性格与优势、判断与选择、相处特点四项各分配25%，根据实际流式接收到的正文字符及字段长度边界估算项内完成量，段落尚未闭合时也可推进；已闭合正文最多99%，整份免费试读校验并保存后才100%。接口以wait=false先返回报告编号，前端持续读取免费进度；预览任务按资料、租约及进程任务表去重，取消前端等待不会重复启动模型，进度接口不返回未校验正文。模型的现有流式输出会持续记录已闭合的正文、标题、示例、提醒、行动步骤等结构字段，未完成字符串及错误类型不计数，每项另保留校验和保存的完成量。七个运程主题及总结建议共八项，各占完整进度的 12.5%；免费阶段的四项进度分配不变。接口返回各项内部百分比与汇总进度，因此章节尚未整体完成时总进度也会更新；草稿字段只计处理进度，不向客户端返回未校验正文，最终校验保存后才到 100%。SQLite 自动添加 generation_progress 列，保留历史内容；旧报告按已保存章节和总结恢复进度。

前端每 3 秒查询真实快照，以 1% 步幅平滑显示；免费阶段显示四项子进度，新运程解析的完整阶段显示八项子进度；历史五主题报告仍使用原来的五项进度。免费达到100%后打开独立报告页，完整达到100%后关闭动画并展示完整正文。HTTP 429 遵循 Retry-After 自动等待恢复，缺失时等 60 秒；普通网络错误退避重试。生成失败时保留已有内容和继续生成入口，取消只结束页面等待。系统减少动态效果或视频不可播放时显示静态星芒，真实进度继续更新。设备访问密钥以本地存储及会话存储保留；均不可用时先提示启用存储，避免生成后丢失查看权限。

“保存为 PDF”直接在浏览器生成实际 PDF 文件，使用嵌入的 Noto 中文及泰文字体、A4 自动分页和页码。支持 `showSaveFilePicker` 的浏览器先让用户选择文件名和保存位置；其他浏览器通过下载保存，位置按浏览器或系统设置。取消选择不会生成文件；字体和 PDF 引擎仅在确认导出时加载，不把报告上传至第三方转换服务。未解锁或完整版本尚未生成完毕时，仅导出免费的三部分正文；完整版本解锁并生成后导出免费及完整内容。独立 HTML 另由标有“网页”的保存按钮提供。实际收费前需要将直接解锁入口替换为服务端支付权益判断。

PDF 沿用项目的紫金视觉：首部为深紫星盘与星芒，内页为米白底色、金色编号、浅紫摘要和依据面板，并显示出生资料、解读体系、参考时间范围及页码。装饰采用矢量图形，正文保持可选取和检索；普通行动清单与其标题一起分页，长清单保留自动换页。未知时间仍明确标注估算，不影响免费与完整内容的权限边界。

## 接口与保留内容

新表单向同一个人生报告接口提交 `report_kind: "fortune"`，服务端以 `fortune-reading-1` 和七主题目录生成、保存及恢复内容。没有该标记的历史五主题报告继续使用原目录，职业专题继续使用自己的流程，不删除或覆盖已保存正文。年度标题采用本次报告的年份，不写死参考截图中的 2027。

主题名称、中泰文说明、引用宫位和生成范围共用相邻 TH 项目的 `backend/content/fortune-topics.json`。前端在构建时读取该公开目录，后端从同一文件组装真实生成请求；部署时应保留两个项目的相邻结构和该文件。网页、保存的 HTML 与 PDF 共用 `reportContent`，免费导出不会包含付费正文。

`GET /api/thai-locations?country=CN&level=province` 返回对应国家的完整省府目录；`level=locality&province=geonames:...&query=...&offset=0` 按省府浏览或检索市区，每页 100 条；`level=detail&query=geonames:...` 按地点 ID 恢复历史报告的省府信息。原有 `level=auto` 自由文本识别与 `level=city` 城市目录保留供其他页面使用。`POST /api/life-reports` 提交出生资料和年份，只生成或复用免费试读；使用 `?wait=false` 立即返回已建立的报告编号和当前快照，随后通过读取接口查询免费内容的 `preview_generation_progress`；不传该参数时等待免费试读完成再返回；`GET /api/life-reports` 读取本设备报告列表；`GET /api/life-reports/{id}` 读取快照与进度；`POST /api/life-reports/{id}/unlock` 解锁并启动完整内容生成，或继续中断的生成；`POST /api/life-reports/{id}/feedback` 保存试读反馈。上述报告接口使用浏览器随机生成并保存在本机的 `X-Report-Key` 区分设备，不修改个人档案。清除浏览器存储会失去本设备报告列表的访问凭据。

地点、坐标及检索别名改编自 [GeoNames](https://www.geonames.org/)（CC BY 4.0）。TH 后端通过 `scripts/build-birth-locations.py` 将 CN、TH、HK、MO、TW 地名包构建为 `data/birth-locations.sqlite3` 离线索引，港澳台归入对应省级选项。当前中国目录 940,791 条、泰国目录 95,619 条，包含现存城镇／聚居地点和行政区，不含历史废弃地点；包括泰国 928 个区县记录。名称及行政沿革以下载时的 GeoNames 数据为准，缺少译名时显示来源名称。省府名称与代表点在 `backend/content/birth-regions.json`。新环境或升级旧索引时，先在 `D:/desktop/TH` 执行 `pnpm setup:locations`，无需在线地理编码服务或 API 密钥；地点查询和排盘解析共用此索引。

TH 后端的 `life_reports.py` 复用真实 Suriyayatra 排盘与主题宫位提取；`life_report_content.py` 为预览、章节和行动清单提供结构与证据校验，并复用现有模型传输、缓存和纠正流程。生成额度按一次试读或一次完整生成计数，内部章节不会重复占用报告次数。提供商密钥仅保留在 TH 后端。旧 `/api/thai-reading` 保留供 TH 项目的原有单主题页面使用。

表单下方的七个锁定主题卡片用于展示报告涵盖的内容，旧示例区域及弹窗已移除。首屏沿用紫袍占星师与紫金视觉，按屏幕宽度和像素密度选择 450、900、1199 像素的 WebP，并使用匹配的响应式预加载；原始 PNG 保留为格式回退。

实际投放前仍需配置正式品牌、隐私政策及实际收费方案。当前解锁是直接展开体验，不能当作服务端付费权限控制。

## Payso 测试收银台

JY 的测试银行卡流程已接入原有订单和解锁接口。默认不启用外部支付，继续使用本地银行卡演示；仅在后端开发环境完整配置 `PAYSO_TEST_MERCHANT_ID`、`PAYSO_TEST_API_KEY`、`PAYSO_TEST_SECRET_KEY` 时，才显示 Payso 测试付款入口。确认付款时由后端查询订单并核对商户、金额、币种、状态及订单号，确认后按原进度生成报告。生产环境拒绝启用这些测试配置。

## 本地运行

先启动 `D:/desktop/TH` 的现有后端（`pnpm dev` 会同时启动其前后端），再在本文件夹运行：

```powershell
pnpm install
pnpm dev
```

打开 `http://127.0.0.1:8765/?lang=zh`。Vite 开发服务将 `/api` 请求转给现有后端 `127.0.0.1:8000`。

```powershell
pnpm test
pnpm build
pnpm test:e2e
```

`dist/index.html`、`dist/app.js` 和 `dist/style.css` 是原页面的生效源文件；`dist/report.html`、`dist/report.js` 为独立报告页入口，两页复用 `src/` 中的 React 18、TypeScript 和 Tailwind CSS 组件。构建产物输出到 `site/`，保留 `dist/` 中的源文件与原有素材，不再直接用静态服务器运行源码。

TH 后端默认在构建完成后挂载同级本目录的 `site/` 到 `http://127.0.0.1:8000/thai-landing/`，与报告接口同源。部署到其他位置时可通过后端环境变量 `THAI_LANDING_DIR` 指定构建目录。构建目录在后端启动时检测，应先构建后启动。

中文使用设备系统字体，泰文使用本地 Noto Sans Thai WOFF2 字体，不依赖 Google Fonts 请求。主标题、表单标题、主题卡片标题和购买按钮使用 700 字重的无衬线风格，卡片说明使用 500 字重；仅顶部 FATE 标识保留原来的 Georgia 衬线字形和字距，收银台标识仍采用无衬线字形。页面在应用脚本运行前确定语言，中文首屏无需下载泰文字体。PDF 继续使用独立的完整嵌入字体。

用户开始填写表单时预载压缩后约 1.67 MB 的报告视频，首屏不请求动画资源。点击生成后，文字与首帧画面同时显示；视频尚未解码时先显示带轻微呼吸效果的首帧，解码后接续播放。关闭弹窗会暂停视频，减少动态效果模式不请求视频。生成进度仍依据真实报告内容更新。

自动浏览器检查使用人工合成的报告拦截数据，避免消耗商业接口额度；实际排盘与生成使用 TH 后端原有的配置和额度限制。服务器构建、缓存、数据保留与更新步骤见 [部署说明](deploy/README.md)。
