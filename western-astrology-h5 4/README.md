# FATE 运程解析

本地 H5 已迁移为 **Flutter Web**。当前页面入口为 `web-client/lib/main.dart`，页面、表单、报告、收银台和路由均由 Dart 实现，构建产物仍输出到 `site/`，继续使用相邻 TH 项目的原有 Python 后端。APP 工程在 `../TH/app`，本次 H5 迁移没有改变其业务范围。

原 React 页面、旧样式、Vite 页面配置与旧 DOM 浏览器脚本已经移入 `tmp/retired-react-ui-20261110/`；迁移前还保留完整 ZIP 备份。仍使用的 `src/lib` 类型、双语目录、HTML/PDF 文档生成函数及相应检查继续保留，作为无界面的文档工具；页面运行不加载 React。当前架构与验收结果见 `docs/FLUTTER_H5_MIGRATION.md`。

整个落地页的排版、页面效果、交互和动画以 JY 分支为主，框架保留本地 Flutter Web、GoRouter 及原 Python 后端。当前包含 JY 欢迎页、人物过渡、紧凑出生资料表单、浮动地点候选、预设及自填问题、两块泰式主题图板、三阶段生成和完整解锁页。默认泰语，右上角可以切换中文，品牌标识为 FATE。具体取舍及验证见 [JY 页面合并记录](docs/JY_UI_MERGE_20261111.md)。

## 预览入口

- `/`：泰语整体星盘页（默认）
- `/?lang=th&topic=love`：泰语感情页
- `/?lang=zh&topic=love`：中文审稿版
- `/?lang=th&topic=career`：泰语事业页
- `/?lang=th&topic=life`：泰语整体星盘页
- `/?lang=zh&reading=money`：中文财富解读入口
- `/?lang=th&reading=annual`：泰语全年解读入口
- `/report.html?id=<报告编号>&lang=zh`：独立人生报告页，刷新后读取本设备的同一份报告

## 已实现

移动布局、双语切换、出生日期（阳历）与出生时间、出生地点联动选择、必填校验，以及整份《人生报告》。出生国家单独一行，下方左右分别是省份／府州、市区；三个输入框均有下拉箭头，可以点击选择或输入搜索。候选菜单以浮层展开，不占用表单高度；与输入框等宽并跟随滚动，在键盘或屏幕下缘空间不足时向上显示，点击空白处收起。国家支持中国与泰国，省府目录分别包含 34 个省级地区和 77 个府级地区；市区只在选定省府内检索，上级改变后清空下级。中泰地点支持中文、泰文及英文检索，结果跟随页面语言显示；重名地点需从候选结果确认，缺少译名时使用来源名称。选择市区后采用该地点坐标及时区；选择行政区时提示采用代表坐标。表单、试读、解锁区域和完整报告沿用首屏深紫与香槟金配色。

报告服务保留原有免费摘要、个人特点、七个完整主题及行动建议。JY 页面以六个内容入口展示；已有完整报告将年度与整体归入运势总览，其他原有章节与行动计划完整保留，采用 JY 星盘和六组目录阅读。婚姻情感侧重长期关系，姻缘侧重吸引偏好，风险提醒提供条件性的阻力与应对。星盘使用现有泰式 Suriyayatra 已计算位置，没有改用西洋算法或虚构精确相位。

勾选“不记得确切时间”后仍可生成报告，提交和保存的 `birth_time` 保持 `null`。人生报告在计算环节明确按出生地当地 12:00 估算，不改变其他排盘入口的未知时间逻辑；表单、报告封面、导出文件与计算依据均提示估算及偏差。估算报告和确切 12:00 出生的报告分别保存，模型收到估算标记并按不确定信息解释；历史报告页仍显示未知时间及估算提示。

点击「立即解析」时确认资料使用说明，只生成或复用免费阶段内容。全页按 JY 顺序显示基础信息、星体与宫位、运程解读，进度读取真实生成状态，星球转盘在等待期间持续转动；免费内容完成后进入独立解锁页。测试阶段，「支付并解锁」和「前往下载 APP」两个按钮都调用原解锁接口，开始生成完整七主题与行动建议，完成后显示完整报告。页面保留 ฿39 示例金额，不会创建支付订单、扣款或跳转下载；重复点击会去重。已有完整报告可以从“我的报告”打开并导出，报告仍按原设备随机密钥保存在 TH 后端 SQLite 中，刷新或继续链接可恢复同一份结果。

生成页面采用 JY 三阶段呈现，完成后静音播放一次结束视频；减少动态效果模式不播放视频。原服务的免费和完整内容进度继续保留。免费阶段将摘要、性格与优势、判断与选择、相处特点四项各分配25%，根据实际流式接收到的正文字符及字段长度边界估算项内完成量，段落尚未闭合时也可推进；已闭合正文最多99%，整份免费试读校验并保存后才100%。接口以wait=false先返回报告编号，前端持续读取免费进度；预览任务按资料、租约及进程任务表去重，取消前端等待不会重复启动模型，进度接口不返回未校验正文。模型的现有流式输出会持续记录已闭合的正文、标题、示例、提醒、行动步骤等结构字段，未完成字符串及错误类型不计数，每项另保留校验和保存的完成量。七个运程主题及总结建议共八项，各占完整进度的 12.5%；免费阶段的四项进度分配不变。接口返回各项内部百分比与汇总进度，因此章节尚未整体完成时总进度也会更新；草稿字段只计处理进度，不向客户端返回未校验正文，最终校验保存后才到 100%。SQLite 自动添加 generation_progress 列，保留历史内容；旧报告按已保存章节和总结恢复进度。

Flutter 页面每 3 秒查询真实快照，直接显示实际进度，去掉人为逐百分点等待；免费阶段显示四项子进度，新运程解析的完整阶段显示八项子进度；历史五主题报告仍使用原来的五项进度。校验并保存完成后才显示100%，随后立即打开报告。HTTP 429 遵循 Retry-After 自动等待恢复；普通网络错误退避重试。生成失败时保留已有内容和继续生成入口，取消只结束页面等待。系统减少动态效果或视频不可播放时显示静态星芒，真实进度继续更新。设备访问密钥继续使用原 `astro-life-report-key`，存储不可用时先提示启用存储，避免生成后丢失查看权限。

“保存为 PDF”直接在浏览器生成实际 PDF 文件，使用嵌入的 Noto 中文及泰文字体、A4 自动分页和页码。支持 `showSaveFilePicker` 的浏览器先让用户选择文件名和保存位置；其他浏览器通过下载保存，位置按浏览器或系统设置。取消选择不会生成文件；字体和 PDF 引擎仅在确认导出时加载，不把报告上传至第三方转换服务。未解锁或完整版本尚未生成完毕时，仅导出免费的三部分正文；完整版本解锁并生成后导出免费及完整内容。独立 HTML 另由标有“网页”的保存按钮提供。实际收费前需要将直接解锁入口替换为服务端支付权益判断。

PDF 沿用项目的紫金视觉：首部为深紫星盘与星芒，内页为米白底色、金色编号、浅紫摘要和依据面板，并显示出生资料、解读体系、参考时间范围及页码。装饰采用矢量图形，正文保持可选取和检索；普通行动清单与其标题一起分页，长清单保留自动换页。未知时间仍明确标注估算，不影响免费与完整内容的权限边界。

## 接口与保留内容

新表单向同一个人生报告接口提交 `report_kind: "fortune"`，服务端以 `fortune-reading-1` 和七主题目录生成、保存及恢复内容。没有该标记的历史五主题报告继续使用原目录，职业专题继续使用自己的流程，不删除或覆盖已保存正文。年度标题采用本次报告的年份，不写死参考截图中的 2027。

主题名称、中泰文说明、引用宫位和生成范围共用相邻 TH 项目的 `backend/content/fortune-topics.json`。前端在构建时读取该公开目录，后端从同一文件组装真实生成请求；部署时应保留两个项目的相邻结构和该文件。网页、保存的 HTML 与 PDF 共用 `reportContent`，免费导出不会包含付费正文。

`GET /api/thai-locations?country=CN&level=province` 返回对应国家的完整省府目录；`level=locality&province=geonames:...&query=...&offset=0` 按省府浏览或检索市区，每页 100 条；`level=detail&query=geonames:...` 按地点 ID 恢复历史报告的省府信息。原有 `level=auto` 自由文本识别与 `level=city` 城市目录保留供其他页面使用。`POST /api/life-reports` 提交出生资料和年份，只生成或复用免费试读；使用 `?wait=false` 立即返回已建立的报告编号和当前快照，随后通过读取接口查询免费内容的 `preview_generation_progress`；不传该参数时等待免费试读完成再返回；`GET /api/life-reports` 读取本设备报告列表；`GET /api/life-reports/{id}` 读取快照与进度；`POST /api/life-reports/{id}/unlock` 解锁并启动完整内容生成，或继续中断的生成；`POST /api/life-reports/{id}/feedback` 保存试读反馈。上述报告接口使用浏览器随机生成并保存在本机的 `X-Report-Key` 区分设备，不修改个人档案。清除浏览器存储会失去本设备报告列表的访问凭据。

地点、坐标及检索别名改编自 [GeoNames](https://www.geonames.org/)（CC BY 4.0）。TH 后端通过 `scripts/build-birth-locations.py` 将 CN、TH、HK、MO、TW 地名包构建为 `data/birth-locations.sqlite3` 离线索引，港澳台归入对应省级选项。当前中国目录 940,791 条、泰国目录 95,619 条，包含现存城镇／聚居地点和行政区，不含历史废弃地点；包括泰国 928 个区县记录。名称及行政沿革以下载时的 GeoNames 数据为准，缺少译名时显示来源名称。省府名称与代表点在 `backend/content/birth-regions.json`。新环境或升级旧索引时，先在 `D:/desktop/TH` 执行 `pnpm setup:locations`，无需在线地理编码服务或 API 密钥；地点查询和排盘解析共用此索引。

TH 后端的 `life_reports.py` 复用真实 Suriyayatra 排盘与主题宫位提取；`life_report_content.py` 为预览、章节和行动清单提供结构与证据校验，并复用现有模型传输、缓存和纠正流程。生成额度按一次试读或一次完整生成计数，内部章节不会重复占用报告次数。提供商密钥仅保留在 TH 后端。旧 `/api/thai-reading` 保留供 TH 项目的原有单主题页面使用。

表单下方为 JY 原版主题图板和六项内容名称，替代此前七张大型卡片。人物、视频、徽章和图板均使用 JY 素材；Flutter 内的网页视频组件负责渐隐遮罩、暂停恢复和播放失败退出，界面入口不加载 JY 独立 React 工程。

当前处于直接解锁测试阶段，解锁和 APP 两个按钮均可生成完整解读；正式收费与实际下载入口后续再接入。现有报告的设备归属和查看权限继续由原服务端校验。

## 本地运行

先启动 `D:/desktop/TH` 的现有后端，再在本文件夹运行。Flutter SDK 默认使用本机 FATE 缓存，也可以通过 `FATE_FLUTTER_BIN` 指定：

```powershell
pnpm install
pnpm dev
```

打开 `http://127.0.0.1:8765/thai-landing/?lang=zh`。本地服务将 `/api` 请求转给原后端 `127.0.0.1:8000`；`pnpm dev` 先生成 Flutter 发布构建再启动预览。仅启动现有构建可用 `node scripts/serve-flutter.mjs --skip-build`。

```powershell
pnpm test
pnpm check
pnpm build
```

`pnpm test` 执行仍被使用的 TypeScript 内容契约检查及 Flutter 模型、接口、页面交互检查。`pnpm check` 执行文档工具的 TypeScript 检查与 Flutter 静态分析。构建采用 `flutter build web --release --wasm --no-web-resources-cdn`，先输出到独立暂存目录，验证必需文件后再替换 `site/`；上一份构建移入 `tmp/site-previous-*` 以便回退。默认 base 为 `/thai-landing/`，可通过 `FATE_H5_BASE_PATH` 调整，部署目录必须与构建 base 一致。

TH 后端默认在构建完成后挂载同级本目录的 `site/` 到 `http://127.0.0.1:8000/thai-landing/`，与报告接口同源。部署到其他位置时可通过后端环境变量 `THAI_LANDING_DIR` 指定构建目录。构建目录在后端启动时检测，应先构建后启动。

Flutter 页面使用本地 Noto Sans Thai。中文首屏先加载同源的 348 KB 精简字体，后续地点和报告文字按需补充常用或完整字库，字体外观不变；泰文首页不下载中文字库。符号字体也按界面所需精简。字体准备好后再显示对应的数据内容，PDF 继续使用独立的完整字体。字体授权在 `web-client/assets/fonts/`，生成方式见 `scripts/fonts/README.md`。

JY 原版报告视频约 3.02 MB，只在生成页下载。生成开始即在屏幕下半部分显示星球转盘，轻微叠放在进度卡片上，静音内联循环播放；切换解读阶段或刷新真实进度时，视频持续转动。报告完成后停止循环，当前一轮播完再显示结果。播放失败使用海报并继续等待实际生成结果，减少动态效果时保持静态；动画不会提前完成报告。已有完整报告按 JY 六组目录展示，PDF 和 HTML 仍导出已获权限的完整内容。

Flutter 自动检查使用合成报告；真实链路另在隔离数据库上验证，不修改已有用户报告。报告生成时间与页面加载时间分开统计，打开链接可附加 `startup=1` 输出不含凭据的首屏、报告正文及资源计时。服务器构建、缓存、数据保留与更新步骤见 [部署说明](deploy/README.md)。公网版本使用相同构建产物，实际部署及验证记录保存在忽略的 output/deploy/ 目录。


首屏加载状态直接位于原 HTML 入口中，实际 Flutter 页面完成首帧绘制后移除；图片预加载最多阻塞 700ms，避免 HTTP 渲染路径长时间空白。欢迎页背后的表单在进入时才构建，避免隐藏页面的初始化和图片下载占用首屏。静态欢迎页会继续请求帧直到收到真实绘制通知，避免加载层在页面已经显示后仍不消失。本地预览对引擎、脚本和字体启用 gzip。渲染引擎位于 `site/engine/<SDK revision>/`，部署时可长期缓存；入口和业务资源仍重新验证。测量与验证记录见 [首屏优化](docs/STARTUP_PERFORMANCE_20261111.md)。
